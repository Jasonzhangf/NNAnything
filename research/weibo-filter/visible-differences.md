# 微博呈现差异：连线图的样本依据

状态：观察与用户标定。尚未训练；连线图仍待用户审计。

| 类别 | 当前可见依据 | 本轮目标 | 不应直接作出的推断 |
| --- | --- | --- | --- |
| 普通完整帖子 | 作者区、时间/来源区、内容、互动栏；没有已确认的推广来源标记 | 正例候选 | 没找到标记不自动证明无推广 |
| 平台广告 | 卡片头部第二行可见“广告”小图片；该样本的 DOM 没有对应文字 | 负例 | 小图片的尺寸或文件名本身不是广告真值 |

| 社交推荐 | 作者头部之前有“某某和某某关注了”的独立来源栏 | 用户确认负例 | 作者资料区的粉丝数不是这条推荐来源栏 |

## 已实测的局部关系

- 已确认平台广告的头部标识图片约为 26.125 × 14 CSS 像素，相对卡片顶部约 49 像素；这些是该样本的测量，不是固定识别阈值。
- 当前 DOM 中，用户第二张推荐截图对应的两张卡片都有一条位于作者 header 之前、约 33 CSS 像素高的独立来源栏。
- 同一推荐新闻卡片的作者资料区还有“1811.5万人关注了TA”。它包含相同关键词，但相对卡片的位置不同。标记含义需由区域和内容共同确定。
- 普通帖的会员图标也可能位于头部。必须区分作者身份标识、原创/置顶等状态标识与推广来源标识；当前不能承诺只凭任意小图标就能区分。

## 对手写结构的约束

1. 先比较当前节点内部实际呈现的分区和标记，再确定输入；不先堆叠全局页面特征。
2. 标记的物理位置、所在分区、类型和可见性应明确。原始账号名、class/id、文件名和绝对 DOM 路径不进入模型。
3. 是否允许将固定界面词（广告、荐读、推荐来源语句）编码为标记类型，以及图片标记如何识别，要在连线审计中写明；不能藏成未经实现或验证的 isAd 输入。
4. filter 仍然只接收一个节点的抽象参数。页面采样、遍历、标记定位与参数抽取各有外部职责；filter 不迁移到别的节点。
5. 固定结构与训练参数分别列出。未训练手写基线也要实测；标记稳定时，它可能已经有效，训练收益不能预设。

## 少样本假设

用户认为稳定的呈现标记可能让很少的样本取得高准确率。该假设合理，尚未有实测结果。先从少量已确认样本开始，按新错误补最相近反例，而不是预先采集大量简单负例。

独立帖子/采集批次用于检查泛化，同一原帖及其包装、子节点和重复截图保持在一组。分别报告普通帖、平台广告、荐读、社交推荐和边界节点的误判，不用大量背景节点的正确率掩盖目标/推广误判。
