## 2. 三层职责与首版范围

| 层 | 负责 | 不负责 |

CLI 首版包括 session/cwd、路径原语、目录及属性观测、精确文件名与字面字符搜索、范围覆盖及错误回执。递归使用正常命令的原生能力，不训练逐目录模拟。浏览器首版包括文档与 scope、DOM/几何/焦点/可见性观测、显式绑定动作及安全后验。任意网页自动绑定、帖子等二层业务关系不在本批推荐范围。

基础学习单元分别审计：路径动作、共享命令 policy、DOM 基础种类、SetExpanded 单步、F1 反馈、F2 策略。每项独立报告推理行为、训练生命周期及兼容范围。某项未通过不阻塞无依赖的基础单元或引擎受控验收。

## 3. 统一模型与存量兼容

目标仍是统一输入格式、64 维输入、两层网络、固定推理引擎、动态技能及动态权重路由。四头职责保持 R 关系、D 目标分解、E 当前可评价结果、A 目标到动作映射。权重负责单次决策，引擎负责推进。

存量 CLI 矩阵、路径模型和浏览器单元并非全部满足目标结构。已有拟合与回载证据可以复用，但仅支持原结构、原输入域和原候选。不得补零包装后宣称结构统一，也不得从零重训冒充继承。

先形成各单元的输入/输出、模型结构、实际决策点、权重来源及行为证据清单。兼容入口可独立验收；统一模型推荐须另有编码与继承设计。该差异不阻止固定基础和引擎工程。二层训练继续后置。

## 4. 推理合同与状态迁移

Goal 由调用者明确选择，或由 CLI 入口隐含绑定。它属于训练支持的有限能力。执行中根目标不变。建议字段不是额外用户语义，不因缺某个字段拒绝已有合法入口。

State 的核心是哪些路径仍可推进、哪些 Goal 仍可拆解、哪些结果待评价或回传。复用现有 frame、condition、stack、cursor、continuation；不建立第二套状态库。领域观测、模型判断、证据和预测是材料，分别保存其来源，不代替推进状态。

| 当前情形 | 处理 | 状态变化 |
| --- | --- | --- |
| 当前结果部分可评价 | Evaluate 只评价具备信息的部分 | 其余保留待评价，相关材料变化后重评 |
| Goal 可直接执行 | 选择适用技能并绑定对象及参数 | 执行同一个 Action，读取真实返回 |
| Goal 需拆解 | 保留父条件关联并生成子 Goal | 子结果推进父目标，不能直接宣布根完成 |
| 某路径受阻 | 保留缺口，继续独立路径 | 独立结果可能解阻；根达成则结束 |
| 再次受阻 | 依据当前材料重评旧受阻路径 | 满足前提则恢复，否则保留缺口 |
| 无可推进项 | 处理完待返回结果后停止 | 单独计算 complete、partial 或 incomplete |

执行错误不代表“没有”。待判断关系不补 false。预测不改写为已观测事实。技能缺失不发明新工具。未知 effects 只阻塞确实依赖它的路径。

## 5. Action 从选择到执行

现有 `Selection` 主要返回 `skillId`。同技能可对应不同对象，单凭技能名不能保证执行了已选目标。已观察的 TSJS 路径还存在执行阶段再次评分的风险。

设计在现有 selected 分支中传递最小 typed 决策载荷至 `AtomicInput`：当前 Goal/frame 关联、技能、对象与参数引用、必要的候选依据。执行消费该载荷，不重新评分重选。执行前可以核对适用性；对象失效则返回缺口并重评，不能偷偷换对象。

对于已由 Goal/bindings 唯一确定动作的 adapter，不强制添加冗余字段。只有实际需要区分候选对象时补载荷。首个反例是同技能的 A/B 对象：选择 B 后必须执行 B，selector 只调用一次。

## 6. 评价、终止与返回

复用条件级 `not_evaluated`、`unknown`、`satisfied/unsatisfied`。`not_applicable` 只用于确实不适用的合同。精确事实可用固定 evaluator；这不计作训练 E 头效果。当前引擎验收不依赖新 E 头。

无进展判据看真实相关变化：前提是否改变、义务是否减少、技能是否变为适用、是否有新结果可处理或新 Goal 可推进。日志增长、新 step 编号和再次调用模型不算进展。同一相关状态已重评且没有可推进项时结束，不增设重试次数或训练预算。

公开结果建议包含 `completion`、`results`、`completedItems`、`remainingItems`、`stopReason`、`errors`。名称可沿现有 API 映射；不强改内部 control 枚举。

| 真实情况 | 返回语义 |
| --- | --- |
| 根 Goal 全部达成 | complete |
| 必要范围已查清，确定没有 | complete，空结果与覆盖依据 |
| 尚有范围未查，只是当前没找到 | 不得宣布没有 |
| 部分必要工作完成，本次仍有缺口 | partial，完成列表、成果和剩余项 |
| 已有部分成果但预算耗尽 | partial，预算原因及部分成果 |
| 无部分成果且预算耗尽 | incomplete，预算原因 |
| 无可推进路径但目标未完成 | 按实际完成项返回 partial 或 incomplete |

完成的否定分支也是成果。只有调用成功、扫描了一部分或模型分数较高，不能据此认定必要工作完成。

`--verbose` 返回结构化 JSON 的实际链：Goal/子 Goal、选定 Action、对象、执行与后验、已评价和待评价项、受阻/恢复/停止原因、结果对应的 step 与证据。未执行候选单列。关闭 verbose 不改变执行行为；开启时不重跑模型，不输出内部思维文本，不从日志重建业务控制。

## 8. 基础能力验收

| 单元 | 真实入口与重点 | 必须抓住的失败 |
| --- | --- | --- |
| CLI 固定基础 | 公开 CLI consumer、真实沙盒、同 session 前后状态 | 子进程 cd 冒称持久变化、读取失败冒称空目录 |
| 路径模型 | `createPathResolver` 自主 rollout、原域独立 oracle | teacher 修正学生、支持域外冒称通过 |
| 共享命令 | `createCliCommandPolicy(...).step(...)` 的选择、调用和后验 | unsupported 仍执行、参数错绑、执行成功冒称达成 |
| 精确搜索 | 公开名称/内容搜索、递归范围、one/all | 不完整覆盖称没有、错误转空、遗漏部分成果 |
| DOM 基础分类 | `classifyBrowserBasicKinds`、显式文件 profile、真实前端 | 缺测变 false、unknown 变 ignore、加载失败复用旧权重 |
| 浏览器单步 | `runBrowserSingleActionEpisode`、显式目标和真实后验 | 点击成功替代展开、错对象、旧 scope 后验 |
| F1/F2 | 原公开 infer、原支持域逐例证据 | 新反馈冒称已训练、同分强选、诊断权重冒称训练效果 |

每项须回答模型实际决定什么、固定代码决定什么、失败例如何抓错、真实入口是否使用声明候选、支持域是否覆盖当前用途。优先复用有效拟合/回载证据。保留历史失败与未验证项。浏览器用户入口由测试员实际验收，adapter 和合成证据不能替代。

## 9. 引擎独立验收

使用公开 `nnanything/recursive-goal` 和受控有限技能。建议 consumer 放入 `playground/recursive-goal/foundation-acceptance.mjs`。不得直接调用私有推进函数，也不得在 fixture 中替引擎处理回评、partial 或父子回传。

必须覆盖：默认 Goal；已满足时零动作；同技能不同对象；当前可评价子集；子成功不等于根成功；确定没有；未查完；否定分支部分完成；有成果/无成果预算耗尽；局部缺技能；局部原错；A 受阻而 B 解阻后恢复 A；B 未解阻时保持缺口；相同状态无进展终止；替代路径达成根后停止；verbose 成功及受阻链。

合成 consumer 只证明引擎。通过后用已验收 CLI 技能做真实沙盒接入，再用已验收浏览器技能做受控页面接入。不能把这些测试称为二层学习。

## 10. 分批计划与放行

第一批并行整理基础证据和引擎合同。已有事实先复用；缺证据只限制相应推荐。State、可评价子集、部分成果及重评语义须同步到原合同，保留批准状态与尚未执行的 gate 状态。

第二批按受影响图 → 行为 gate → 公开反例 → 最小修复 → 同入口正反回归推进。runtime 优先解决选择到执行一致性、局部回评、完成投影和实际 trace。无需为此先训练二层模型。

第三批做基础能力与引擎组合验收，形成完整 milestone，由独立 Reviewer 审整体交付，Alice 审语义和证据。通过后才集成并发布有限推荐。公开例子必须说明参数、权重来源、effects、结果状态、原错与 verbose；所有可用能力须进入对应使用文档和 skill。全局安装按适用授权单独处理。

第四批才评估二层研究输入是否齐备。多头训练由研究员设计目标、编码、来源隔离、loss、固定 trainer/evaluator、旧能力回归和停止条件，Alice 审计。记录真实训练耗时、回归执行及语义效果；不以轮次代替训练目标。当前不启动该批。

当前仍未交付的关键项：最新语义与原合同完整同步；基础单元逐项有效推荐证据；引擎局部重评及无进展终止的公开行为证据；完成投影与实际链一致性；存量模型到统一架构的明确兼容结论。本文完成设计，不把这些缺口标为已修复。
