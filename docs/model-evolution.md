# 语义调用与所有模型的自进化

状态：2026-10-19用户明确的目标架构；2026-10-20补齐首域接入顺序与验收，但自动采集、typed当前版本、自动升级与冲突设计修订仍未实现。本合同覆盖CLI、浏览器基础分类器及后续可训练节点。已有离线训练仍输出`not_applied`候选，不因本文更新而自动启用。总体推理合同见[design.md 1.1](design.md#11-结构化语义的目标与状态推理)。本文是跨模型演进与升级规则唯一owner；领域算法、特征与训练I/O仍由原合同维护。

## 1. 语义目标、固定调用、实际执行

推理由语义目标驱动。模型依据Goal和State选择声明的语义动作及参数引用。harness按固定调用合同转成CLI或浏览器实际操作，返回真实结果；目标检查器验证新状态。模型不生成任意shell文本，也不通过自行声称成功来完成Goal。

```text
Goal {kind: observe_cwd, session: S}
→ Action {kind: PWD, session: S}
→ harness: 在S的显式cwd及授权下执行 /bin/pwd -P
→ Observation: 实际物理cwd、stdout、exitCode及来源
→ New State: 更新S的cwd观测知识
→ GoalResult: 根据本次观测检查是否达成
```

调用语法、参数类型、session、授权、输出与错误合同手写且版本明确。模型学习何时调用、参数角色和状态关系。harness负责绑定引用、授权、命令映射和实际观测；不替模型纠正错误选择后把它算成学对。无效调用显式失败。`cd`修改同一会话基准，后续`pwd`验证；一次性子进程退出前的成功不证明会话改变。

浏览器沿同一边界：分类节点输出固定类型的语义结果，动作节点输出固定调用，浏览器适配器执行。基础分类器不因采用本合同就被改成工具选择器；每个模型保持独立职责、特征、损失和评价合同。新增能力先画合同与连线，不让核心内置CLI或站点语义。

## 2. 使用即采集，采集不等于监督

### 2.1 预训练、后训练与结构修订边界

2026-10-20用户进一步明确：每个单元先以足够样本和手写逻辑建立初始能力，并通过独立场景验证泛化。能直接表示为Handwired电路的手写逻辑以显式参数初始化；不能直接表示的逻辑作为teacher产生监督，再拟合并核对权重实现。手工参数、teacher一致率与真实训练结果分别报告，不把代码自动等同为权重。

初始泛化验证通过后，正常演进沿现有语义I/O、特征和决策结构，使用后验数据做后训练。默认不重写手写逻辑、不重做预训练。单例失败、局部退化或训练loss不足，不构成改写逻辑的依据；输入已可辨时，先补复核样本、调整现有权重并回归。

只有证据表明重大参数、必要观测或表示能力缺失，导致一大类场景无法覆盖，才进入结构修订。准入材料须列受影响场景族、缺失参数/输入、现有表示为何无法区分正确结果、补足后的可辨反例及旧能力回归范围。先修唯一图纸、I/O或wire，再实施并重做受影响部分的预训练；没有这类证据时，大模型裁决也不得将普通后训练变成反复重写逻辑。

每个实际执行阶段形成可追溯的后台评分记录：当前Goal与阶段、学生真实输入和选择、使用profile、实际回执/New State、目标评价、奖励/惩罚及归因依据。奖励规则由该单元合同声明；根达成、阶段进展、无效操作、错误选择、环境拒绝、观测不足与unknown分开。环境或执行器故障不直接惩罚语义head；unknown不补零奖励或负奖励；未执行备选没有成功奖励。阶段信用不能因共享证据而重复累计，也不能将预测当实际奖励。

后台评分是训练证据准备，不表示每次执行即时改权重，也不限定必须使用某一种强化学习算法。采集、评分、监督复核、隔离后训练、保存回载和独立评价沿现有单元升级DAG；控制层序、权限、真实验收和账本不作为奖励驱动的放宽项。候选须旧能力无回归且独立泛化更好，才按第4节自动采用；冲突仍沿第5节处理。当前持久采集、阶段评分、后训练调度和自动采用尚未实现。

每次模型使用自动采集是单元升级的必需功能，不是可选手工步骤；不要求每次使用立即训练。记录适用的 Goal/satisfactionThreshold/State/Action 及实际结果。采集失败须显式记录，升级链不得宣称闭合；未受影响的业务使用继续按其实际结果报告。

每次模型使用默认产生本地样本记录。记录语义请求、学生实际输入、模型输出、当时使用版本、执行回执与可获得的前后观测；失败、未知、冲突、代表性成功都保留。领域不适用字段显式说明，例如纯分类没有实际动作。缺少原始证据不能在之后根据变化的页面或文件系统补造。

采集owner为对应adapter/consumer，形成已声明I/O后交给训练模块；不让filter写文件或让core解释领域数据。记录使用现有事件合同及本地`training/samples/`目录，不另建执行引擎。浏览器资料仍仅在本地，继承已有采集与人工标注边界。

模型输出只是预测。只有复核过的标签、可验证的实际状态转换或明确teacher证据才可成为监督；unknown、过滤项、未确认other和无回执动作不能自动变负例或黄金标签。训练集自身复核与独立验证分开，场景家族先划用途再生成；用于诊断、调参或连线修改的验证样本转为开发/回归证据，新一轮未见评价另留独立批次。

### 2.2 逐步经验与纠正的时间边界

每步经验分别关联：决策前真实可得输入与证据、当时模型/规则版本及输出、适用时的候选/预测、实际调用及回执、真实后验、事后评价/解释、纠正建议及来源。来源区分实际观察、手写teacher、人或LLM复核、模型预测/自我解释。原始决策输入和选择不可因后来知道答案而改写；补测须保留取得时点，不能变成当时已知。

学生真实走到的错误状态可以用于纠正学习，但预测错误与实际环境变化分开。结果预测以真实后验监督；选择纠正只使用该次选择前可辨的信息；执行偏离后的下一步从实际State开始，不能复制理想State假装纠错。teacher建议不等于实际效果，未执行备选无成功标签；依赖未来信息而无法判错的旧选择保留未评估，不强造负例。

监督分别归属基础识别、动作选择、结果预测、组合/排序或反馈归因。OS失败不同时惩罚全部单元，观察失败不自动改变基础gold。规则初始化、teacher一致率、真实拟合与行为泛化分别报告；分层唯一原则沿[design.md 1.1.1](design.md#111-可训练基本单元与组合)。

最小验收：t0依据旧证据选A，t1发现前提变化，t2建议B。保留t0原输入，t1只用于之后决策或有来源的后验监督，t2记为建议；B未执行不得记成功。历史未记录的候选/输入标缺失，不从日志或最终State重建控制真源。这是现有领域经验的关联要求，不新建跨域统一schema或采集服务；通用`collect`当前不保证持久保存所有决策输入，领域接入须明确缺口。

### 2.3 期待反馈单元的在线学习

在线学习是必要设计目标：使用中自动记录当前决策与结果期待，执行后采实际观察与反馈，将有来源监督送入隔离的增量训练；通过原有采用条件后更新后续请求。单个任务内先靠反馈更新State、失败先验与路线，不要求每一步立即改变权重。在途请求/continuation沿原绑定完成，不能半途混用新候选。

LLM设计二层语义训练时，须一并交付决策期待、正确/错误/无效/未知后果的观察逻辑、语义评价监督和纠错样本，不能只训练动作选择。结果预测只用当时可得输入；实际New State用于后果监督；评价器用独立oracle、teacher或复核来源评估，不用它自己的分数生成黄金。执行错误、预测错误、观察错误和目标未满足分别归因。

首个在线实验限定一个领域单元：按预声明使用批次采样，复核监督，真实后训练并保存回载，在新任务上与未更新baseline配对比较恢复和成本。缓存与参数学习分别报告。没有合格新监督就保留数据待复核；预算失败停止该训练配方；冲突/回归不自动更新；有明确提升、必需旧能力无回归、独立证据与兼容性满足时沿第4节自动采用。具体训练触发规模、算法和数值预算归领域实验合同，不新建一套全局调度或采用服务。

本节是接入要求，不表示目前已有全项目自动在线链。领域实现须分别给采样、监督、训练、回载、配对评价和版本切换证据；缺一项如实报告未闭环。

## 3. 使用版本与训练候选隔离

训练是权重升级的必要步骤。升级必须有监督复核、真实拟合、候选保存及回载、独立新能力评价与旧能力回归；采样完成、仅改参数文件、loss 下降或大模型建议均不能替代。已有有效训练证据可复用，不要求无变化重训。

当前使用版本只读，训练在另一个候选上进行。一次请求开始时绑定一个完整使用版本，结束前不混用新旧权重或新旧特征。训练不原地修改当前模型，候选保存也不等于采用。

权重允许通过显式资源热重载，在新请求边界生效。失败案例可固定原输入、真实回执与评价标准，对多组候选做可重复对照，保留逐例差异供大模型分析回归原因。加载失败必须显式返回，不能用旧候选冒充新版本；在途请求与续接保持原binding。数值对照不能证明实际动作成功，真实重执行须受控并保持未知effects/inflight不重放。热重载不绕过真实训练、独立泛化及无回归采用条件。首个候选实验实现由[有界决策单元](bounded-planning-decision.md)维护，不代表全模型热重载或自动诊断已接入。

版本是相互兼容的一组合同与参数：语义I/O、特征变换、外层workflow、内部数值连线、权重、适用时的harness映射及校准状态。沿既有节点/workflow版本与显式profile资源管理，不建立哈希清单或第二个注册服务。权重拟合使旧校准失效；未校准不伪装成概率。

自动升级由单一采用owner修改显式当前版本引用，不能从日志、样本metadata或候选文件名推断当前版本。切换完整兼容版本，在新请求边界生效，在途请求用原版本完成。比较时的基准若已被其他候选替换，本候选保留待比较，不覆盖更新后的版本；重新与实际当前版本比较。浏览器和CLI采用相同原则，各模型可独立演进；跨节点连线不自动反传。

## 4. 全面更强且无回归才自动升级

“全面更强”按预先声明的能力合同判断，不要求每个已经正确的样本都严格变好。当前版本与候选在同一独立样本及适用真实执行场景上配对比较，并保留各自合法的特征提取路径。

| 必需条件 | 判断 |
| --- | --- |
| 至少一处明确提升 | 存在经复核的能力修复或预先声明目标指标的严格改善；只降训练loss、改置信分数或减少未知不能独立作为升级理由 |
| 旧能力无回归 | 所有必需旧黄金、逐例正确行为、错误状态与副作用约束保持；不能以修复多例抵消退化一例 |
| 独立证据完整 | 新独立验证及要求的场景/类别有足够证据；未覆盖、缺测、不可比或未验证不算通过 |
| 合同与运行兼容 | I/O、图、特征、harness、权重与校准状态匹配；适用真实入口验证通过 |
| 无待决冲突 | 没有标签冲突、同输入相反真值、策略冲突或未归因的退化 |

全部满足时自动触发采用，不增加人工确认步骤。没有提升但无回归则保留当前版本；证据不足则保留候选待验证；存在冲突或回归则禁止自动升级，保留当前版本及冲突记录并提交大模型裁决。不得降低既有门槛、删难例或改黄金标签来取得自动升级。

逐例结果继续使用`fixed / regressed / retained / unresolved / unassessed`。每个必需目标独立比较；分类节点报告类别与识别状态，动作节点另报动作选择、参数绑定、执行结果和实际GoalResult。总体准确率不能掩盖某一能力退化。性能指标只有在该模型合同声明为验收项时才参与，不凭空增加门槛。

## 5. 冲突留下，大模型诊断并修改设计候选

大模型对回归/冲突给出裁决、依据及下一动作：保留当前版本、拒绝候选、要求补证或提出修复。不能只归档而不移交处理；未决、无法判断或处理失败均保留当前版本。仅在需要改变设计时修图，不强制每个冲突都改连线。裁决不直接覆盖权重或豁免必要训练与验收；修复后以新一轮重新验证和处理采用。

冲突记录包含当前与候选输出、相同原始输入、监督依据、真实效果、首次偏离及涉及图/合同。保留原始冲突，不让训练直接吞掉。大模型可以处理标签或证据问题，也可以更改设计连线；先判断失败owner，不能将执行器或采集错误全部塞给权重学习。

普通冲突先在既有结构内修复样本、证据归因或权重。只有满足2.1节的重大覆盖缺口条件，才允许以预训练结构修订处理特征、数值wire或决策连线；执行器、采集器和harness的实际bug仍在各自owner修复，不冒充模型重做预训练。需要改图的修复先改唯一图纸和合同，再做图校验、受影响gate、红测、owner实现、适用训练与独立验证。不能仅改图就修改在用版本，也不能用更换reviewer绕过冲突。用户目标、业务策略和黄金语义不是可随意优化的参数。

每轮有限执行：冲突诊断输出下一轮设计候选，下一轮重新进入训练和评价；不在DAG中加回边，不让大模型在运行中直接改写当前模型。没有冲突不必调用大模型；满足完整升级条件可自动切换。

## 7. 首域接入顺序与验收

首域选CLI共享命令模型。它的使用入口已经有typed Goal/State、实际执行结果、显式profile和候选训练/新进程回载入口，现有缺口比浏览器动作或DOM分类更小。这里只接一个域的既有入口；不要求其他单元同步迁移，也不新增统一模型注册表、第二调度器或跨域样本schema。

### 7.1 现有入口映射

| --- | --- | --- | --- |

`lib/workflow/compiler.ts`中的`profiles`映射只是本次编译的显式资源，不是持久当前版本记录。`lib/nodes/cli-command.ts`的`onSample`也不是自动训练器。上述入口都不能从日志、候选文件名或样本metadata反推“当前版本”。

### 7.2 实施任务顺序

全部任务保持设计态，只有在对应代码、红测和真实入口证据完成后才能改为已实现。顺序如下。

| ID | 任务 | 唯一责任与动作 | 验收与停止条件 |
| --- | --- | --- | --- |
| EV1 | 定义CLI typed当前版本资源 | CLI owner在`lib/cli-goal.ts`及其显式领域资源中区分候选工件、当前版本引用和一次请求的绑定；模型演进图只负责决策语义，不新建注册服务。训练产出的候选文件仍保持`uncalibrated/not_applied`，当前版本不能由日志、路径或文件名推断。 | 候选文件与当前引用可分别加载；非法合同、缺profile或未完成采用决策显式拒绝；现有profile校验器仍拒绝非`not_applied`候选。未完成此任务时不得进入EV4。 |
| EV2 | 接通CLI本地使用采集 | `lib/nodes/cli-command.ts`保留`onSample`领域外壳，调用者注入显式本地sink；sink返回可恢复ReceiptRef。样本包含Goal、阈值、State、预测/策略、实际调用、执行结果、实际后状态、满足度、状态、证据和请求绑定版本。 | 成功、失败、unknown、rejected及采集失败均有可重复用例；采集失败只产生显式采集回执，不改变原业务status、satisfaction、effects或错误；样本不自动成为黄金监督。未配置或写入失败时升级链明确`collection_incomplete`并停止受影响训练/采用。 |
| EV3 | 隔离训练、保存和回载候选 | 复用`runCliCommandTraining`及现有CLI训练consumer；从显式基础版本训练到新候选目录，使用`wx`或等价拒绝覆盖。候选保持未校准、`not_applied`，不原地修改当前资源。 | 新进程显式读取候选并运行相同公开推理；候选来源、训练样本分区、回载结果与当前版本引用分别可读。没有独立评价也不得宣称可采用。 |
| EV4 | 独立配对评价并产生采用决策 | 评价owner使用独立作者准备的verification和旧能力回归，在同一输入上配对当前与候选；`model.evolution.compare/assess`唯一形成评价与`adoption_decision`，再由`model.evolution.adopt-or-hold`产生`adopted / held_no_improvement / insufficient_evidence / retained_conflict`回执。 | 至少一处预先声明提升、全部必需旧能力无回归、证据完整、合同兼容且无待决冲突才返回`adopted`。未知、缺测、不可比、整体分掩盖单项退化或同输入相反真值均不得通过。 |
| EV5 | 单一采用owner切换新请求 | 只有已实现的`model.evolution.adopt-or-hold`可修改显式当前版本引用；CLI公开入口在每次新请求admission时绑定一个完整版本，在途请求保留已绑定版本完成。 | 采用后新请求使用新版本；采用前已开始的请求继续使用旧版本；两请求不混权重新旧特征；候选文件、日志或样本写入都不能直接改当前引用。基准已被替换时保留本候选待重新比较，不覆盖新当前版本。 |
| EV6 | 冲突保留与LLM裁决移交 | 回归、冲突或未归因退化由`retain-conflicts`形成受限冲突记录并交给`model-conflict-design.graph.json`。只有冲突子图的`model.conflict.diagnose`可给出保留、拒绝、补证或设计修复建议。 | 冲突保存当前与候选输出、原始输入、监督依据、实际效果、首次偏离及涉及合同；未决或裁决失败时当前版本不变。LLM只输出诊断或设计候选，不直接改当前引用、权重、黄金标签或权限。 |

`retain-conflicts`位于唯一汇流路径，但这不等于所有采用结果都上报冲突。其typed结果必须区分：

| 采纳结果 | `retain-conflicts`输出 | 是否调用LLM |
| --- | --- | --- |
| 无冲突，已采用或无需采用 | 返回`model_conflict_receipt`并携带`adoption_receipt`，记录`conflict_transfer=none`；不生成冲突条目 | 否 |
| 无改进而保留当前版本 | 返回`model_conflict_receipt`并透传保留原因，记录`conflict_transfer=none` | 否 |
| 证据不足 | 返回`model_conflict_receipt`，状态为`insufficient_evidence`并保留待补证状态 | 否 |
| 明确回归、冲突或未归因退化 | 保留当前版本，形成冲突记录，记录`conflict_transfer=required` | 是，交既有冲突子图 |

采集失败在比较与`retain-conflicts`之前收束为`collection_incomplete`，不训练、不采用，也不发送给LLM。它不能被转换成空冲突记录或成功样本。

因此，无条件图边只表达单入口单出口的汇流责任；分支是否移交由`retain-conflicts`的typed结果决定。实现无冲突透传不需要改现有拓扑，也不得把空冲突记录写成LLM已裁决。

### 7.3 非目标与完成边界

- 不新增共同大接口。`lib/core/trainable-unit.ts`的薄`infer/train`合同可继续供领域复用，但首域接入不要求CLI、DOM、单动作、反馈和策略同时重构。
- 不训练递归层序、是否继续或重试次数。CLI首域仅学习命令/控制head及既有参数角色，不涵盖上层排序/语义分解；这不是对后续独立可训练语义能力的禁令。浏览器`collectRoot`只采集完整运行证据。
- 不放宽现有各profile校验器。当前CLI命令/路径/CWD关系、DOM、单动作、反馈和策略候选继续`uncalibrated/not_applied`；EV1完成前，自动采用没有合法的当前版本资源。
- 不改动`workflows/model-evolution.graph.json`或`workflows/model-conflict-design.graph.json`。本节只明确现有节点的分支语义和验收；若实现typed结果需要改变对象端口或边，先按受影响图重新设计并校验，不能由worker直接越owner改图。

## 8. 当前实现边界

单元升级与语义设计是两个独立 SESE 对象流，均由 DAGpipe 管理。升级复用 model-evolution 图，不另建同义图。升级自身四元素为：Goal 是改善该单元且保持必需旧能力；satisfactionThreshold 是预先声明的改善验收阈值（无回归是必要条件，不能用总分抵消）；State 是当前版本、样本、候选及实际评价证据；Action 是采集、复核、训练、比较、采用或保留并移交裁决。各阶段输出包含完成或具体缺口，失败/证据不足不继续受影响训练或采用，统一收束到本轮回执。跨轮补证和修复重新进入，不加回边。大模型裁决由既有冲突子图消费保留记录，主图回执明确裁决移交状态，不能把移交当作裁决已完成。

已有部分采集、离线拟合、候选保存、逐例比较及公开consumer回载。使用时全模型自动采集、统一版本引用、自动采用门槛及LLM改图的完整执行链尚未交付。当前候选继续`not_applied`。后续实施必须先接通采集与隔离，再接通配对评价及自动采用，最后接通冲突设计修订；每项先有对应图纸与可重复真实入口证据。
