# 可复用、可积累经验的节点合同

状态：L1 候选切片已交付；当前增量推进三类基础采样节点实现（`0.1.0`），2026-10-17。用户要求每个实现节点本身可复用、可积累经验。本合同定义节点合同规范。节点卡唯一真源维护于 [lib/nodes/README.md](../lib/nodes/README.md)，工作流清单维护于 [workflows/README.md](../workflows/README.md)。

## 1. 一个节点是什么

节点定义是一项具有明确输入输出的能力。节点实例在workflow中绑定参数与可选profile。业务流程的顺序属于workflow；网页遍历和浏览器环境属于场景适配器；数值连线属于可训练节点内部。单个节点可在多个workflow中复用。

每个将实现的节点必须有一张简短节点卡，内容如下。所有节点卡唯一真源集中维护于 [lib/nodes/README.md](../lib/nodes/README.md)，实施计划与各目录仅做链接引用。无需为此引入机器manifest或全局注册表。

| 字段 | 必须说明的内容 |
| --- | --- |
| 身份 | operator、合同版本、能力范围与唯一owner |
| 输入 | 事件类型、端口名、字段/编码、必需/可选与缺失语义；数组顺序及项关联 |
| 输出 | 事件类型、结果数据，以及成功/过滤/跳过/未知/错误的含义 |
| 配置与状态 | 明确参数、状态来源和引用；不得依赖隐藏页面、站点或全局当前profile |
| 副作用 | 所需effect能力、读/写对象和后条件；未知结果不能自动重放 |
| 训练能力 | 手写或可训练；可训练时声明特征顺序/变换、目标编码、数值电路与参数约束/损失 |
| 兼容条件 | 输入/输出及参数结构的版本；哪些配置/profile可加载，哪些变化需新合同 |
| 验收 | 一个真实公开consumer、必要正反例、适用失败模式；不能只验证内部函数存在 |

NodeDefinition不要求全部节点具有训练能力。viewport/黑白名单等手写经验可以通过规则或实现修复积累；训练节点通过参数/profile与规范样本积累。两者都留下对应回归用例，不将每条经验强塞成神经权重。

## 2. 复用有三个层次

1. 复用实现：相同合同下，在不同workflow中引用同一个operator，实例配置独立。
2. 复用适配结果：同一输入编码/目标/数值连线下，选择兼容profile；站点profile不把站点名称变成学生特征。
3. 复用经验与验证：经复核的成功/失败案例、规则修订和回归证据可用于相同任务，保留来源关联与适用范围。

不同目标或输入编码不兼容时，建立对应合同或新版本。网页节点不必适用于图像/文件输入；跨场景主要复用节点合同、通用节点和训练机制。组合workflow以后可用明确I/O封装为复用子流程，但D0不要求先实现子流程引擎。

## 3. 经验积累路径

运行记录关联实际node/operator版本、配置/profile、输入与输出证据。失败回溯先定位首次偏离，再决定修复owner：候选遗漏修过滤/枚举；错误标签先纠正规范真值；可辨输入下的误判修参数；缺乏证据返回特征/连线设计；操作失败检查执行器或页面状态。

进入训练或回归的经验必须引用规范样本及标签来源。重复事件不是新独立样本；更正已吸收标签时替换规范真值，不累计矛盾证据。LLM可以提议标签与归因，提议不自动变成黄金样本或生效权重。

一次可采用的修复留下：适用节点与合同、修复类型（规则/参数/特征/连线）、规范样本引用、候选产物、旧新逐例比较和采用结论。记录采用实际版本/产物引用，不增加哈希身份包装。原始证据本地保存，Git只存适合分享的规则、合同和脱敏fixture。

训练用旧训练回放集与选定新样本，独立回归集检验退化。候选profile不自动覆盖当前版本；新拟合使校准失效。缺少独立样本时明确development-only/uncalibrated，不把拟合loss降低当作泛化成功。

这条路径允许节点能力逐步积累。首轮先实现可重复的离线修复/比较，不承诺每次操作后自动在线更新，也不将普通热启动冒称贝叶斯后验。顺序贝叶斯、预测关系协同属于后续独立策略。

## 4. 第一浏览器场景的具体关系

观测、手写过滤、DOM拆分、特征提取、分类和汇总分别是可复用节点。当前DOM元素是处理数据项，不等于画布或workflow节点实例；数组中的每一项复用同一处理能力。

基础采样三节点（`sampleMatchNode`、`sampleAssembleNode`、`createSampleSaveNode({allowedRoot})`）经 `nnanything/browser` 导出：
- `sample.match` 采用三值逻辑（true/false/unknown）求值规则，输出确定性单语义分类与状态，缺失字段不推断为未匹配，已知命中且竞争类别缺测判定为 unknown，多类命中判定 conflict，输出槽位彻底剥离 teacher 原始 class/id/文本，无训练正负极性概念；纯函数 `evaluateSemanticRules` 独立可用；
- `sample.assemble` 组装单任务训练样本，按任务显式映射各语义到正负监督并保留原始语义结果，标签来源固定为 `rule_proposed`（不冒充黄金真值）；学生观测严格限定为白名单字段（fresh tag/role/rect/fragments/clippedRect/parentRef，支持合法负视口 CSS 坐标 x, y），过滤/跳过候选标为 excluded，未判定标为 unlabeled，无候选状态不假定通过 L1 约束；
- `sample.save` 绑定调用者显式提供的已有 `allowedRoot`，使用 `create_new`（wx）排他写入，严格拒绝逃逸、符号链接与覆盖，写失败显式暴露；调用者须控制根目录不被并发篡改。

结构识别节点目标为 post.card，广告在结构上也可为完整卡片。普通帖/广告/推广属于后续来源任务，必须有可辨输入再增加节点或兼容变体。完整节点合同卡唯一维护于 [lib/nodes/README.md](../lib/nodes/README.md)。

D0验收只核合同与计划是否完整、可执行、可独立验证。节点的运行可复用性、修复收益和跨站效果，须在后续实现阶段由真实consumer证明。
