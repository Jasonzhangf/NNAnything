# CLI读取实验：基础反馈、结果语义、下一Goal与语义收敛

2026-10-24设计任务，尚未实现或训练本实验。用户要求先验证读取动作：读取数据及其通用特征、读取错误和错误后的合法操作；不理解数据业务含义。它是编程搜索M1的基础实验，不能把搜索字符串是否命中混入本读取单元。

## 1. 整条设计链

根Goal是取得指定对象的头部、尾部或范围数据，声明数量单位与数量要求。决策前给出需要满足的条件、结果期待与观察方式；执行真实读取，基础单元识别实际反馈；推理单元解释反馈对当前Goal的意义，输出下一语义需求；需求编译为已注册子Goal或准确返回；子Goal证据逐层回到未丢失的根Goal。

这是对外可审的设计链：目标条件→决策结果期待→已知操作→实际观察→基础反馈→正向/负向/未知的目标关系→下一合法Goal→根评价。反复发生在既有recursive-goal控制器中，不训练层序、继续计数或预算。

“语义收敛”指当前语义义务已被真实证据满足，或已经收束成明确失败/证据不足/不可执行结果，不再有需要且允许继续衍生的子Goal。收敛结果分成功、明确错误、未知；失败停止不是目标成功。仅NN分数稳定、错误重复或没有生成新Goal，都不能证明成功收敛。

## 2. 用什么命令/技能

| 已有能力 | 本实验职责 | 训练责任 |
| --- | --- | --- |
| directory.list（共享policy中的ls） | 仅在需要时观察候选/父目录，不读正文 | 复用已训练policy，不重训 |
| entry.inspect | 取得普通文件类型、身份、大小与当前引用证据 | 复用已知能力，不从文件名猜类型 |
| file.read(ref,offset,length) | 在受信沙盒中取得真实字节/回执或准确错误 | 固定执行器，不新增自由shell或命令selector |
| 路径绑定/结果返回 | 参数机械构造、引用校验与报告 | 手写基础设施 |

用户层语义为read head、read tail、read range。它们不是新增三个CLI命令head。字节范围的算术由harness精确计算，NN不猜offset或伪造字节。共享cli.command-policy.v1保持唯一且权重不变。

首个可用增量只做bytes；随后在同一实验扩head/tail的lines与Unicode code points。range首版只接受byte offset。LF/CRLF、末行无换行、UTF-8跨块、零长度、空文件的计数规则由独立Plan先固定。字符数不冒称用户感知字形数。非法UTF-8的byte读可成功，字符特征保持未知/解码错误，不能伪装为读取失败或强行理解内容。

数量要求显式区分up_to与exact：up_to N允许EOF时少于N；exact N在已确认EOF且不足N时不能满足Goal。不能修改请求数量取得成功。返回原始数据与已测通用特征，例如字节数、约定行数/字符数、实际范围、完整性、EOF与错误；正文不进入本实验NN语义特征。

## 3. 基础能力训练：读文件反馈学习

训练一个ReadFeedbackUnit，沿统一infer/train接口，消费真实回执/观察的显式事实，输出基础反馈及证据引用。原始数据本身由读取器返回，精确计数由测量器计算；模型不能重新生成数据、猜计数或修饰errno。

| 基础反馈 | 通用特征/证据 |
| --- | --- |
| data_obtained | 有当前读取回执和字节，包含实际范围与bytesRead |
| end_observed | 有足够证据确认文件端点；可与数据取得同时成立 |
| incomplete_observation | 请求所需观察未齐、读取范围未覆盖或必要计数缺测 |
| execution_error | 真实操作错误，保留stage/code；不是无数据即有错误 |
| target_changed | 身份/绑定失效或读取前提变化证据 |
| observation_unknown | 无当前可用观察，不能声称成功、EOF或无效果 |

这些是状态及事实，不要求互斥成一个标签。独立Plan固定最小可训练输出形状，例如主反馈状态加已测属性；不能把真实同时成立的数据+EOF强拆成冲突标签。基础训练只学对读取结果的语义识别，不学正文用途、字符串命中、代码含义或文件role。

训练监督由原始OS回执、独立读取oracle、明确测量规则与受控错误注入产生并复核。注入与真实OS错误单列；缺测不填false。必须包含空文件正常读取与错误无输出、合法零长度与失败零字节等可混淆反例。

## 4. 推理训练：反馈语义生成下一Goal

训练一个ReadReasoningUnit：输入根Goal/当前子条件、决策前期待、基础反馈、已确认State与可用技能；输出有来源的结果语义、当前下一需求及参数引用。它不输出整段计划，也不自己派发命令。

结果期待包含：本步要取得什么特征，做对/不足/错误时应观察什么，哪些事实仍不可预知。未读文件的隐藏字节不能成为期待模型的训练答案；可以期待“读后取得结果”，不能监督模型预知未观测正文。

| 对当前Goal的结果语义 | 示例 | 可选下一语义需求/Goal |
| --- | --- | --- |
| 条件已满足 | 当前对象/范围/数量均有真实证据 | 验证并归还本子Goal；根条件齐全则返回成功，不再衍生无用读取 |
| 有数据但仍缺必要数量/范围 | 已有两行，需要三行，未确认EOF | 取得剩余数据：file.property.content.bytes observed的剩余范围子Goal，再更新行数 |
| 正常端点已到 | up_to请求少于N但确认EOF | 本读取目标可达成；不是read_error |
| 已证数量要求不可能满足 | exact请求不足N且确认EOF | 返回实际不足；不重复读取同一EOF，不把Goal改为up_to |
| 当前对象需重新确认 | stale引用、大小前提变更 | entry.inspect的当前身份/大小观测子Goal；依根绑定规则决定能否重新签发/继续 |
| 可安全重试的读取未完成 | 有来源的瞬时错误，当前身份/权限仍有效 | 同一读取语义的新尝试；仅在控制器允许的次数与条件内 |
| 当前授权/类型不允许读取 | 拒权、非普通文件、越界 | 返回准确错误或缺能力；不生成chmod、sudo、换用户或越界读取Goal |
| 无法判断实际结果 | 缺回执、缺观察或结果冲突 | 有合法观察技能则补观察，否则unknown；不硬判成功/失败 |

同一errno不固定映射唯一下一动作：是否已有当前身份、原Goal是否绑定同一对象、重试是否允许，都能改变合法候选。训练应包含只改变这些条件就改变正确选择的配对样本。ENOENT不意味着自动改读另一个文件；解码失败不意味着自动改变用户指定编码；读取错误不意味着全部retry。

输出先形成有限的领域语义，例如need_remaining_data、need_current_target、retry_current_read、condition_met、terminal_error、need_observation；再由固定编译绑定到已有Goal/返回合同。只有确实需要操作的需求衍生子Goal，condition_met与terminal结果应收束，不能为了“形成链”无限生成Goal。

必要条件/权限/预算与引用仍由harness守卫。错误学生不得被规则静默改成正确答案，错误与真实执行/根事实分别记录。成功、失败与未知样本都参与相应监督；多个合法等效后续需求用允许集合，不强定唯一层序。

### 4.1 从结果到下一Goal的统一推导

每步分别回答三个问题：操作实际发生了什么；这些事实满足了当前Goal的哪些条件；剩余条件中，哪个可以由当前合法技能继续取得。正向/负向是相对Goal的关系，不是操作回执的别名。读取成功但数量不足可以产生后续需求；读取失败但取得明确拒权证据可以使本次尝试准确结束。二者都不能仅凭exit code判根成功。

下一Goal不是任意新意图，而是保留根Goal约束的条件缺口：目标对象、范围、数量要求和权限不能在衍生时偷偷改变。领域模型学习“反馈与缺口的关系、哪种合法操作能补该缺口”；固定绑定器将所选语义及参数引用构造成已有typed Goal，控制器执行并重新观察。缺少所需技能时显式返回缺能力，不生成自由命令。

| 链路职责 | 学习内容 | 保持确定性的部分 |
| --- | --- | --- |
| 基础反馈 | 从已测通用特征识别取得数据、端点、错误、失效或未知 | 读取字节、计数、原始errno、身份和权限事实 |
| 目标关系 | 识别满足、尚缺、已证不满足或证据不足，并保留依据 | 原始Goal、阈值、请求范围及证据来源不变 |
| 下一语义需求 | 选择补数据、补观察、确认对象、合法重试或准确返回 | 参数引用构造、技能准入、预算与重试计数 |
| 反向归还 | 学习型评价适用时评价语义条件 | 当前子Goal证据归还父层，最终重新核根条件 |

例如“exact读取头部8字节”：本步取得3字节且端点未确认，基础反馈是data_obtained；结果语义是仍缺5字节；下一需求是need_remaining_data；绑定为同一对象剩余范围的内容观测Goal。后续取得5字节，先归还该子Goal，再合并无重叠且当前有效的范围证据，核验原8字节要求。若后续只取得2字节并确认EOF，则准确返回不足，不能修改原要求或把已读5字节判为达成。该例的分段大小是场景条件，不要求执行器为训练人为制造短读。

### 4.2 语义收敛与控制停止分开

成功收敛要求根Goal的所有必需条件都有当前真实证据。明确不满足要求的收束，要求证据足以支持其适用范围内的结论；“本次授权下不可读”不能扩大为“文件永远不可读”。未知返回表示证据或能力不足，不证明目标不可达。

预算耗尽、取消和重复无进展是控制停止，不是语义已被证明收敛。它们必须保留已读事实、未满足条件与停止原因。模型没有输出下一Goal也不是收敛依据。候选仍有合法可达路径时，模型提前terminal属于推理错误；控制器不将其包装为成功。

未来扩展到其他CLI操作时，逐项建立同一张“结果事实→目标关系→下一需求”表，复用该链路，不将各操作的具体反馈混成一个错误标签：

| 操作族 | 正常结果及目标关系 | 负向或不足结果 | 可衍生的下一语义需求 |
| --- | --- | --- | --- |
| read（本实验） | 取得所需范围/数量 | 范围不足、已确认EOF不足、错误、引用失效 | 补范围、确认对象、合法重试或返回 |
| directory.list（后续组合） | 取得指定范围的条目与覆盖事实 | partial、范围错误、拒权 | 补覆盖、确认目录或返回；partial不能证不存在 |
| entry.inspect（后续组合） | 取得当前类型/身份/属性 | 对象缺失、失效、缺测 | 按根约束重新绑定/补观察或返回；不得静默换对象 |
| 字面搜索（上层M1） | 有当前范围内的命中证据 | 完整范围已证不含、覆盖不足、读取错误 | 换合法候选、补覆盖或处理读取前提；不含不等于read失败 |

本表后三行只规定设计方法，不宣称已完成其训练。二层语义的可复用性来自条件缺口、证据和下一需求的显式合同；不能据本读取实验通过就宣称任意CLI语义可泛化。

## 5. 训练方式与输入边界

两个单元组成ReadExpectationFeedbackGroup，使用真实Handwired后端、显式独立profile及保存回载；不是替换共享命令policy。LLM/独立Planner先给最小I/O、数值wire、标签/允许集合、损失和可辨反例，再实现。正文、路径标识、fixture ID、错误注入开关、oracle答案不进数值输入；只消费已声明的读取通用特征、Goal条件及合法技能信息。

模型1学习读取反馈；模型2学习期待/反馈与目标条件、下一Goal的联系。精确计数和区间算术保持确定性。错误/恢复不能被同一预测自证；独立oracle保留原字节与真值，仅作监督/评价。

初次拟合建议单次200 epoch、同起点，epoch 0及每50记录分类/允许选择、必需错例、有效参数更新与loss。具体lr/损失由独立Plan按数值结构固定后开训，不搜索到绿。地址未参与训练、输入异gold冲突、负监督不进loss或NaN/Inf立即停止受影响配方；达到上限未满足必需行为就FAIL，不自动2000。

## 6. 两套沙盒与样本

复用filesystem-sandbox、cli-read与recursive-goal，不写第二执行循环。训练/开发/测试使用fresh根、session与独立来源配方；setup有创建权限，agent只读。只调用受审已知helper，不操作真实用户文件、不执行项目代码、不联网。现有沙盒为固定调用与引用/根范围隔离，不冒称任意进程的OS隔离。

最小样本族覆盖：普通非空；空文件；零长度；请求到边界；超过EOF的up_to/exact配对；跨读取块；无末尾换行；UTF-8计数；错误无数据；当前引用失效；真实拒权；受控瞬时错误与重试耗尽。每类有真实证据或准确标明的注入。来源先分train/dev/verification，再生成不同大小、名称、内容和数量变体；不能仅换文件名算新实现家族。

先用少量明确手工场景检查可辨与可表达，再扩有限数据。独立Plan列准确场景数/状态数与分母，不用重复同构数据撑准确率。未观测正文相同与否不影响结果语义标签；同一状态只变exact/up_to、是否当前或可重试资格时，正确下一需求应出现有依据的差异。

## 7. 验证：命令成功、反馈正确、链式收敛分别验收

1. OS层：独立readFile/受控fixture oracle逐字节核对返回数据、范围及通用特征；原错误保留，搜索动作零写入。先核对现有file.read的eof字段实际合同，尤其精确到端点、零长度和短读，不用未经验证的布尔含义训练。
2. 基础层：反馈的正常/EOF/不足/错误/失效/未知与原始证据一致；不判断正文语义。
3. 推理层：反馈生成合法下一需求；只在适用证据范围更新State；不重复已证EOF、不无条件retry、不静默换目标文件。
4. 链路层：至少真实执行“分段读取→未足量反馈→剩余范围Goal→继续读取→根收敛”和“受控一次瞬时错误→合法重试Goal→实际读取成功→根收敛”。正常错误停止、耗尽与unknown也要闭合。
5. 泛化层：新实现家族、新文件/内容/数量/块大小；同一个执行器、权重与控制器，无按fixture/站点特判。分报新数值与新状态组合，不宣称任意未知语义。

首选可错或不够高效，错误反馈和假成功不可接受。故意错选/故障注入单列恢复测试，不能算模型自然首选成绩。每条轨迹记录执行前期待、真实回执、基础反馈、结果语义、衍生Goal、证据、控制/原子账本和根结果。

## 8. 在线学习与效率验证

先使两个单元的闭环成立，再在本单元接通使用采样→有来源监督→隔离后训练→保存/新进程回载→新任务配对评价。在途版本不变，候选保持uncalibrated/not_applied；采用沿model-evolution，不新增采用规则。

比较固定基线、初训候选和使用后训练候选：预算内根成功、恢复率、准确停止、重复错误、read/inspect/观察次数、底层读取量与返回量分开。新任务数量与内容变化，同任务缓存单列。真实提效必须保持根结果与错误边界，且预声明的至少一项路径成本改善；无收益就报告未证提效，不反复扩样本/加epoch。

head/tail字节算术本来可直接完成，不能为显得有学习而故意劣化harness。可优化点优先选lines/codepoints的分段读取及必要观察选择：用已观测密度/剩余需求等通用特征选合法读取范围，不能预知隐藏内容。若这一最小实现没有选择空间，先诚实交付反馈/纠错学习，效率阶段保留待证，不伪造收益。
