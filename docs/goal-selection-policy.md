# 通用目标候选与路径偏好策略

## 目的与边界

本文件是通用目标候选、组合关系、路径投影和偏好排序的唯一设计 owner。它回答三个问题：候选或路线是否合法；合法对象之间依据什么比较；比较不足时为何停止并返回 DEFER。

本文件当前是设计合同，不是导出 API，也没有代码、样本、权重、训练或运行绑定。候选对象、路径投影字段和字典序规则均未进入现有入口。未来实现须先补受影响图、gate、红测和真实入口验收；本轮不把设计状态写成已运行能力。

通用选择只消费已有真实 State、证据、权限和 typed 资源。它不派发动作、不执行补证、不改根 Goal、阈值或绑定，也不把预测 State 写成实际 New State。动作执行、实际后验、checkpoint、路径生成与预算生命周期仍由[有界目标规划](bounded-goal-planning.md)及既有 recursive-goal 控制 owner 管理；本文件只消费该 owner 给出的路径投影。

现行第一层“单任务单标签”、F2 的 `margin > 0` 才选择且同分 DEFER、CLI 控制 head 和 recursive-goal continuation 合同保持不变。通用偏好不覆盖这些运行语义。

## 四元素与责任

| 元素 | 本设计中的最小含义 |
| --- | --- |
| Goal | 在不变根 Goal、阈值、绑定、权限和证据要求下，选择一个合法候选或合法路线，或明确 DEFER；选择本身不产生根 Goal 达成事实 |
| satisfactionThreshold | 当前 Goal 显式给出的 0..100 要求；只决定该 Goal 的实际或预期满足度如何解释，不是准确率、模型置信度或统一产品门槛 |
| State | 候选/路线引用、任务阶段、评价尺、实际或预期结果、硬条件、证据覆盖、风险、成本、typed 顺序、unknown 及显式偏好 policy |
| Action | 先过滤不合法对象，再按声明比较键排序并返回选中项、有界有序备选或 DEFER；不执行候选动作 |

选择结果至少保留 `rootRef`、候选或路线引用、`metricRef`、结果阶段、合法性结论、比较键、各键值、unknown、policy、选中项或 DEFER 原因。原始回执、实际 effects、错误、预算和 checkpoint 仍由原 owner 持有，不复制到选择结果。

## 候选输入与四类数值

候选引用必须绑定明确的 Goal、对象、scope、有效 State 和适用条件。引用失效、绑定改变、证据 revision 过期或权限撤销时，不能继续比较或派发；旧排序结果随之失效。

四类数值必须使用不同字段和不同含义。

| 数值 | 含义与使用边界 |
| --- | --- |
| `rawScore` / `margin` | 学生或领域规则输出的原始分数差；可用于该单元自己的合同判断，但不等于满足度、概率或偏好 gold |
| `expectedSatisfaction` | 待执行动作或路线在声明适用条件下的预期结果；可为 unknown，必须带来源和条件，不得复制 logit |
| `actualNewStateSatisfaction` | 实际 New State 按当前 Goal evaluator 得到的结果；只能来自真实观测/执行回执 |
| `preferenceRank` / `utility` | 仅在合法且同尺对象之间按显式 policy 得到的排序结果；不是 Goal 满足度，也不能反向证明动作成功 |

用户给出阈值 90 时，只保存该 Goal 的 `satisfactionThreshold=90`。它不表示要求全模型达到 90% 准确率。二元目标的实际满足度仍可为 0 或 100；部分满足度只在领域合同明确时使用。

`expectedSatisfaction` 和 `actualNewStateSatisfaction` 不得混用。已观测候选使用实际值比较；待执行候选可用合法预期值排序，但选择、派发或计划打印都不能写成“实际达成”。没有已执行 actual 不是自动排除待执行候选的理由。

分段路线可以先到达可评价的阶段 checkpoint，而不在本段达到根阈值。阶段义务与根义务分别验收，不能把根阈值90套到任意局部节点上，也不能用checkpoint的100分冒充根100分。领域若声明预期门槛，它也只是预测筛选依据，不是实际达成事实。

`rawScore`、未校准 `margin`、预测成功、动作派发、实际 effects 和根 Goal 达成是不同事实。任何一项都不能自动替代其余项。概率只有在独立校准合同成立时才能使用；本设计不对未校准分数做概率运算。

## 可接受集合 gold 与偏好 gold

监督和评价至少分成两层。

| gold 层 | 回答的问题 | 不允许混入 |
| --- | --- | --- |
| 可接受集合 gold | 在当前 Goal、硬条件、证据和覆盖范围内，候选是否属于本阶段合法可处理集合；已观测结果还须核对实际阈值与必要条件 | 风格偏好、数组位置、原始 margin、未声明顺序、待执行 expected 冒充已达阈值 |
| 指定偏好 gold | 在可接受集合内部，按当前显式用户偏好或 policy 应如何排序 | 放宽硬条件、改变阈值、把偏好项写成唯一可接受项 |

可接受集合 gold 先于偏好 gold。一个候选被标为“可接受”，不表示它是首选；被标为“非首选”，也不表示它不合法。待执行候选进入合法可处理集合，只表示它允许被考虑或尝试，不表示预期或实际达标；其 expected 只能参与允许的偏好排序。

可接受集合、逐候选实际满足度和偏好顺序需要分别记录。已观测候选的接受判断消费 actual 和必要条件；待执行候选若缺少接受所需的观测，就保留 unknown，不倒填 actual。

风格或显式顺序只改变偏好 gold 和选定结果。风格不能改根 Goal、`satisfactionThreshold`、权限、证据要求、实际 effects、L1 基础类别 gold 或候选资格。未来偏好训练只学习可接受集合内部的当前排序，不训练合法性 gate、阈值、预算、checkpoint、是否继续或递归层序。

## 基础职责解耦与组合关系

基础职责独立指每个成员的 Goal、显式 I/O、State、参数/profile 和副作用 owner 清楚，不依赖隐藏站点状态，也不复制同一实现。独立不要求统计独立：成员可以共享输入特征、相关样本、显式关系、共享 profile 或同一证据，只要来源和 owner 可审计。

组合只声明当前问题需要的关系，不建立通用效果代数。

| 关系 | 最小表达与比较含义 |
| --- | --- |
| 全部必需 | 所有必需成员或其真实结果都满足条件；一个成员高分不能抵消另一个必需成员失败 |
| 替代路径 | 满足任一合法路径即可；未选路径不自动生成失败义务，也不要求全部执行 |
| 前置依赖 | 前置结果或证据成立后才允许使用后继；预测前置不能授权动作 |
| 覆盖或共享证据 | 显式声明一个证据可支持哪些成员；被共享证据只计一次覆盖，不按引用次数累加 |
| 互斥 | 两个结果不能同时成立或同一对象状态不能同时拥有；冲突保留为 unknown/conflict |
| 有序干扰 | 后一动作可能抵消、失效、重绑或覆盖前一结果；旧 satisfaction 和旧引用必须重新评价 |

组合不得把子项 satisfaction 求和得到父 satisfaction，也不得乘未校准概率合成成功机会。父子同分或父子同时保留可以合理，但父 Goal 仍由父 evaluator 对最新真实 State 判定。任何成员错误、unknown effects 或失效证据都不能被其他成员的成功隐藏。

共享证据只增加“有多少成员可由该证据支持”的映射，不增加独立覆盖次数。不同路径跳到同一结果叶、同一内容或同一观测 revision 时，记录为重叠，不记成两份进展。相同文案、相邻节点或视觉重复也不自动证明语义重复；必须沿显式对象归属和证据引用判断。

抵消操作必须撤销相关预测、备选入口、持续条件和旧引用的适用性。历史回执保留，但其 satisfaction 不再代表当前 State。unknown effects 不能补成 none；依赖变化或重试的候选沿既有安全边界停止，只允许已声明的只读补证。

## 合法性先于偏好

每个候选或路线先经过同一 admission 顺序：

1. 核对根 Goal、对象、scope、State、评价尺和 revision 绑定。
2. 核对必要条件、证据有效性和结果覆盖范围；未知保持未知。
3. 核对权限、effects 边界、预算、retry、ledger 和领域适用条件。
4. 区分已观测结果与待执行动作，并确认比较对象同尺。
5. 形成可接受集合，再应用显式偏好 policy。

权限空集、未满足前置条件、失效绑定、未知 mutation effects、超预算或不可接受的副作用，均为硬失败或 DEFER；偏好不能越过这些条件。只读补证只有在当前领域合同明确允许时才能成为下一步，不由通用选择器自行发明。

已执行但未达标的结果仍保留原始满足度、错误和 effects。选择器不能删掉它来“筛光”动作，也不能因为后续候选预期更高就把未执行预期写成已达成。已观测结果候选按实际满足度和必要条件形成可接受集合；待执行候选按合法预期值参与允许的排序。

只有当前比较确实需要的键才要求存在。缺键只阻断依赖该键的策略；序优先策略在硬条件成立且有唯一显式顺序时仍可选一个合法路线，但不能称其为分数最优。

## 路径投影

路径比较只消费[有界目标规划](bounded-goal-planning.md)给出的投影，不重建路径、不管理 checkpoint、不推进 cursor。最小投影为终点评价、覆盖的结果叶、领域风险等级和动作成本。

| 投影字段 | 默认聚合 |
| --- | --- |
| 终点评价 | 对声明覆盖的每个结果叶取最低的根预期满足度或 checkpoint 评价值；必须同根尺，或由领域提供共同进展尺 |
| 风险 | 取域内可比较的最高风险等级；不同风险词表不能直接比较 |
| 成本 | 取各结果路径累计成本的最大值；各动作成本单位必须显式一致 |
| 覆盖 | 保留声明覆盖的叶集合、共享证据引用、未知叶和截断 frontier |

终点评价不能把不同 checkpoint 的局部分数直接比较。没有同根尺、共同进展尺或明确领域映射时，该路径与其他路径不可比。若声明覆盖内存在影响结论的 unknown，路径保留 unknown；不得补 0、补 100 或删除该叶来得到确定排名。

替代路径按 OR 关系评价，不把全部备选变成 AND 必需项。某一路径满足根 Goal 时结束，不为追求更高预测分继续执行另一路径。路径内有共享证据时只计一次覆盖；兄弟节点或相似包装不自动合并，也不自动重复计分。

“有界最优”只表示当前实际生成且可同尺比较的候选集合内的排序结果。预算截断、未展开分支、未覆盖结果叶或 unknown 使搜索不完整时，结果只能标为局部选择，不能声称全覆盖最优。未覆盖世界结果不获得成功保证。

序优先策略可在预期 score 缺失但 typed 顺序唯一、硬条件满足时返回首选合法路线。该结果含义是“按声明顺序的首个合法路线”，不是“已验证分数最高”。

## 比较键与字典序

比较键次序以显式 policy 为真源。数组首项、文件顺序、日志出现次序、候选创建时间、字符串排序和未记录的默认规则都不能破同分。

| policy | 比较键顺序 |
| --- | --- |
| 分数优先 | 当前阶段适用 satisfaction 降序，再 typed 尝试顺序升序 |
| 序优先 | typed 尝试顺序升序，再当前阶段适用 satisfaction 降序 |
| 保守 | 领域风险顺序（较低风险优先），再 satisfaction 降序，再 typed 尝试顺序升序 |
| 激进 | satisfaction 降序，再领域风险顺序（较低风险优先），再 typed 尝试顺序升序 |

“当前阶段适用 satisfaction”在已观测候选中指 `actualNewStateSatisfaction`，在待执行候选中指 `expectedSatisfaction`。两类对象原则上分组比较，不把 actual 与 expected 拼成同一分数序列。

保守和激进只改变合法候选的排序优先级。激进可因更高预期收益选择较高风险路线，但仍须通过全部权限、effects、预算和证据硬条件；保守不能把未知风险当作低风险。

所有声明比较键都精确相等时返回 `DEFER`。没有另行声明的容差合同就不认“近似同分”。只有声明顺序键仍相同也不能按数组位置选择；显式 typed 顺序不是数组位置。

缺少当前 policy 需要的键时返回 `DEFER/POLICY_KEY_MISSING`，或请求领域合同允许的只读补证。策略完全未声明、比较尺不可比、覆盖不足或其他选择依据缺失时，也返回具名 DEFER，不制造默认偏好。

字典序逐层比较，只对尚未区分的候选使用下一键。主键已经产生唯一合法胜者时，不要求未用到的次键存在；主键仍并列且必要次键未知时才因该键DEFER。显式序优先已得到唯一顺序者无需预期分；保守策略若已由合法风险键唯一分出胜者，也无需预期分。

## 选择结果

选择结果限为以下 typed 语义：

- `selected`：返回合法首选及命中的比较键。
- `ranked`：返回完整可行范围内的有界有序备选，标明覆盖是否完整。
- `DEFER`：返回缺键、未知、不可比、同分、硬条件或覆盖不足原因。
- `NO_LEGAL_CANDIDATE`：声明范围内没有候选通过硬条件；不得用最高分候选补偿。

`selected` 不表示动作已派发、actual 已取得、checkpoint 已满足或根 Goal 已达成。后续执行必须复核最新 State、绑定、权限和 effects，并以实际 New State 重新评价。选择结果不得修改 policy、root、阈值、checkpoint 或预算。

偏好训练、预测转移训练和执行控制是三类能力。偏好训练只消费可接受集合内部的偏好监督；预期 satisfaction 的预测能力需要独立 I/O、来源分区和评价；checkpoint、继续、重试次数、层序和预算由控制层决定，不训练。

## 可审计案例

下列已观测结果案例比较的是当前已经提供的结果集合，不要求执行动作收集全部候选。真实根Goal一旦满足，执行侧先结束，不为调用本选择器继续搜索或操作；在现有结果上选择要返回哪项，也不产生额外环境动作。

| 案例 | 预期结论 | 所抓失败模式 |
| --- | --- | --- |
| Goal 阈值 90；实际二元满足度为 0 或 100 | 保留阈值 90；0 未达标，100 达标；不改写为 90% 准确率 | 把 Goal 阈值冒充模型准确率 |
| 已观测 A=92、B=96、C=94，三者同尺且合法 | 分数优先选择 B；结束于首次实际达标，不继续追求更高分 | 用原始 margin 代替 actual |
| 已观测 A=B=C=95，显式顺序 C/A/B | 分数优先按顺序键选 C；若没有顺序或其他键则 DEFER | 从数组首项破同分 |
| 待执行 A/B/C 预期 92/96/94，风险低/高/中，尝试顺序 C/A/B | 分数优先选 B，序优先选 C，保守选 A，激进选 B；四者都不声明实际达标 | 风格改写阈值或把预测当事实 |
| 待执行预期 unknown，只有唯一 typed 顺序且硬条件成立 | 序优先可尝试首个合法项；分数优先DEFER；保守在风险也缺失或并列需要score时DEFER，风险已唯一分出胜者则不强求score | 未执行 actual 被当作排除理由，或编造 expected |
| 同一候选预期 96，实际 88；另一候选实际 92 | 前者实际未达标；后者实际达标即结束 | expected 与 actual 混用 |
| A/B/C 实际均不低于 90，用户指定偏好 C>B>A | 可接受集合 gold 为 A/B/C 三项；偏好 gold 首选 C；风格变化不改接受集合 | 把偏好 gold 当可接受集合 gold |
| 同一按钮有两种确认等价的原子 provider | 按显式候选和各自真实证据比较；未确认等价的对象不得互相广播成功 | 把相似对象或同文案当等价 |
| 父容器和子文本同时保留，覆盖同一内容证据 | 两者可同时合法；共享证据只计一次覆盖；子满足度不能相加成父满足度 | 假重复、求和满意度 |
| 两条替代路径满足同一根 Goal | 任一合法路径可满足；不要求执行全部路径；未选路径不生成失败义务 | 把 OR 备选写成 AND |
| Goal 阈值 80；路径 P1 覆盖叶 94/88，风险中，最大成本 4；路径 P2 覆盖叶 92/96，风险高，最大成本 2，且同根尺 | P1 默认投影为最低 88、风险中、成本 4；P2 为最低 92、风险高、成本 2；两者先通过阈值，再按显式 policy 排序，不先求平均 | 用平均分掩盖最差叶 |
| 两条路径拥有相同结果叶和同一证据引用 | 该叶只计一次共同覆盖；各自新增叶才增加覆盖 | 共享证据重复计分 |
| 一个动作把已展开区域重新折叠 | 旧展开结果、后继入口和持续条件失效；历史回执保留但不再支持当前达成 | 抵消后继续使用旧 satisfaction |
| 路线含 unknown effects | 依赖该 effect 的 mutation 不进入合法集合；仅允许合同声明的只读补证 | unknown 被补成 none |
| 路径有未覆盖结果叶或搜索被预算截断 | 保留 unknown/截断 frontier；只可称当前生成集合内的局部选择 | 冒称全覆盖最优 |
| 已观测结果与待执行预期放在同一排序表 | 分组比较；若 policy 无法定义跨阶段尺度则 DEFER | actual 与 expected 拼成同一序列 |
| 显式 order-first、唯一 typed 顺序，没有 expected score | 选择首个合法路线，但结果说明为顺序选择而非分数最优 | 序优先结果冒充分数证明 |
| 两个候选所有声明键完全相等 | 无其他显式键时 DEFER；有显式 typed 顺序时按顺序 | 用数组首项、日志或容差破同分 |
| 风险词表分别为 low/medium/high 与 reversible/irreversible | 无领域映射时不直接比较；保留不可比结论 | 跨词表数值化伪造风险 |
| 原 F2 两候选同分或 margin 非正 | 保持原合同 DEFER；通用 policy 不得覆盖 F2 | 新偏好修改现有运行 gate |
| 偏好 gold 把 C 排第一，但 C 权限为空 | C 仍是不可接受项；偏好不得使其进入合法集合 | 偏好越过硬条件 |
| 模型 raw score 很高但 expected/actual 均 unknown | 不能选为满足度最优；只能走不依赖该 score 的合法策略或 DEFER | margin 冒充 satisfaction |

## 未实现与接入条件

当前没有通用候选类型、路径投影类型、选择器、偏好训练样本、权重或公开 consumer。未来接入前至少需要领域明确评价尺、合法 expected 来源、风险/成本词表、typed 尝试顺序、覆盖来源和独立 preference gold。

实现顺序应为：领域合同闭合 I/O → 受影响图与 gate → 红测覆盖合法过滤、四类分数、同分、缺键、路径聚合和 unknown → 唯一 owner 代码 → 公开入口黑盒回归。预测模型、偏好模型和控制层分别验收，不以一项通过代替其余。

本文件不定义 checkpoint 生命周期、路径生成算法、动作执行或模型采用。上述能力分别沿有界目标规划、recursive-goal、动作领域合同和[模型演进](model-evolution.md)的既有 owner 推进。
