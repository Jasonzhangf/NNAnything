## 审计结论

知乎143条未知的当前13项基础属性全部有键；应测结构字段没有null。role不存在、非input没有inputType属于不适用，不是缺测。未知或评分不足不自动证明输入／框架有缺陷，应先区分标定、权重和参数入口。

已经观测的父子关系存在于浏览器观测包；当前单节点BasicKindProperties与训练白名单没有关系、子元素种类组成或几何输入。真实补采136条唯一对应，另7条不强行关联。相同span／单可见子元素／无直接文字输入，实际可以包住链接、按钮、段落或另一层包装。当前数值向量不能表达这种局部组成差别；这不证明这些行标签必然不同，但明确了容器包含关系新任务需要审计的表示边界。

同一输入对应不同局部组成的分组，知乎32组807节点、小红书32组863节点、微博46组1569节点。它们是输入信息合并，不是分类错误数。很多全零wire来自script/style或SVG内部primitive，不需要据此自动增加类别或打分。只有复核目标要求不同而现有表示不可分时，才补必要输入或连线。显式0系数可训练，profile中缺少的地址不参与当前稀疏拟合；能通过配置补既有wire地址的问题不修改框架。

搜索框唯一冲突已核对为INPUT/type=text/role=combobox，父LABEL，childNodes为空。显示文字是控件呈现内容，不是独立候选。当前文本输入与选择角色评分竞争；本轮没有手写例外、调整阈值或开始训练，也没有仅凭冲突就决定增加readonly参数。

已有事件、节点和DAG执行框架可复用；标注、采集和训练现图均未改变。当前没有正式的保留／忽略训练目标合同，也没有跨过已确认忽略包装层的公开语义投影节点。它们属于新目标的接口缺口，不是当前基础种类权重故障。
