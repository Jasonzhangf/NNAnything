## 1. 执行框架与配置

候选采用[Flowed 1.15.0](https://github.com/danielduarte/flowed)的单进程异步依赖调度；DAGpipe CLI保留静态图校验。原因与源码证据见[选型依据](../research/workflow-engines.md)。不接入Rust/TS桥，不新写并行调度器。画布为可选编辑入口，不在本轮实现。

可执行WorkflowDefinition分三部分：

| 配置部分 | 含义 | 唯一来源 |
| --- | --- | --- |
| graph | 输入ARC、节点/operator版本、连线、输出ARC | 对应项目.graph.json，直接加载，不在代码中手抄第二套拓扑 |
| bindings | 各节点实例的config及可选profile引用 | 当前workflow调用/配置 |
| profiles | 本次可用的兼容参数与校准状态 | 明确加载的profile产物，不隐藏读取全局当前版本 |

NodeDefinition由代码提供类型化端口、配置验证、处理器、effect声明和可选训练适配合同。配置只引用已提供的节点，不携带可执行脚本、任意导入路径或上游模板表达式。通用核心用场景无关的schema/capability标识；DOM类型只在应用层定义。

编译层先检查图、端口、绑定、profile与调用者授予的effect能力，再转换为Flowed requires/provides/resolver配置。Flowed负责实际依赖等待、异步节点和汇合。输出事件包含本次执行及输入项关联，不能跨run或跨项拼接。成功、过滤、跳过、未知及错误保持明确语义。

允许的effect能力由调用者提供，workflow文件不能自行授予能力。离线训练/回放不包含真实浏览器动作。用一个可观测effect测试节点验证未授权调用次数为0；本轮不为此实现完整operation-episode的7个网站操作节点。该图继续保持设计态。

## 2. 第一批节点与交付闭包

| 组 | 当前需要的能力 |
| --- | --- |
| 通用 | 明确规则过滤、有序数组转换、结果汇总；不依赖浏览器或训练后端 |
| 网页识别 | 已保存观测输入、viewport/focus、deny/allow、DOM层级拆分、展开项资格检查、白名单特征、单标签判断、保序汇总 |
| 节点训练 | 输入与标签准备、来源关联分组和用途分区、拟合、校准、配对比较、评估和候选profile报告 |

下表是后续核心功能层的节点闭包，不是能动层必须一次实现的清单。能动层仅实现最小候选输出链；识别与训练项目图在核心层组合。已有页面测量供后续离线consumer；本轮不采集或运行consumer。显式nodeRefs数组保长保序；页面拆分按确定顺序保留中间容器及后代，跳过父节点自身不误剪后代。

首个模型只承担当前观测足以支持的结构实验任务。完整卡片结构和内容来源分开：广告也可能是完整卡片，不以“来源特征都低”推导普通帖。广告/推广/推荐目标仍属长期需求；尚无可辨学生输入的目标明确未支持，不输出伪分类或准确率。

Handwired由调用者显式指定源码根；缺失报错，不硬编码本机默认路径、不自动搜索或复制源码。每个实验节点的数值连线、特征顺序及参数约束在实施前纳入本次设计评估；旧10维organic草案不能未经适用性审计直接当公共网络。

本轮8输入9参数结构电路的候选取参定义和连线见[结构电路审计稿](structure-circuit-m1.md)。采用header/footer等可观测结构事实，不以站点class或正文词定位成分；尚未验证可分性。原有organic初始标签不得自动升级为结构黄金标签，结构实验标注需明确记录新target及复核来源。

训练产出候选profile和报告。候选必须能由同一目标节点重新加载。新拟合使旧校准失效；独立校准不足时返回identity及uncalibrated状态。同一快照/帖子/广告素材关联的传递闭包不跨用途分区。初始微博单快照不能证明泛化或独立校准。

## 3. 后续核心功能层的行为验收设计

1. 通用公开consumer运行不含DOM字段的workflow；非法环、未绑定端口、类型不兼容及缺少effect能力时明确拒绝。
2. 网页公开consumer执行完整候选、取参、判断与汇总链；父容器跳过不丢后代，deny不能被allow复活，过滤/未知不压缩显式数组。
3. 模型取参不受class/id/账号名/正文名称变化影响；缺必需观测时不调用数值模型，不将未知当0或负类。
4. 真实Handwired前向/反传和拟合可纠错；新profile可加载，不兼容profile明确拒绝。
5. 训练workflow验证独立分组、校准失效/不足、旧新版本逐例比较与退化报告；不执行网站动作。

后续用可复核、多来源组fixture验证框架行为；真实微博资料只提供开发期观察。作者完成各层适用验收后，再按完整milestone边界Review、合入main并推送。当前D0只验收合同、图和计划完整性，远端已由用户指定，不运行上述业务验收或声称模型已训练。
