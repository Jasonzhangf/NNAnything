# 推进节奏、交付与审批

本规则形成于D0，2026-10-17。项目采用DAGpipe与AppSDK治理原则；范围内agent派发不单独授权；按最小必要性分四层实现；删除不必要SHA与校验。L1已交付，当前用户明确授权实现基础采样节点（nnanything-sampling-l1），旧范围 hold 仅对本次采样增量解除；历史范围保留为历史，L2-L4 仍为后续规划。

## 1. 四层优先级

| 优先级 | 完成度 | 推进原则 |
| --- | --- | --- |
| L1 | 能动 | 最小真实入口能执行并返回诚实结果；只做当前路径需要的节点，达到该层验收即停 |
| L2 | 能有核心功能 | 补齐目标语义、真实训练及兼容profile回载等核心闭环，不加入远期扩展 |
| L3 | 完善功能 | 按真实使用缺口完善语义查询、错误样本修复、操作后验证等功能 |
| L4 | 提高兼容性 | 核心有效后再扩展站点、DOM变体、布局/环境适配；用同类任务证据评价迁移 |

L1-L4表示实现层次。每层开始时明确本轮入口、必需节点、结果和停止点；后续层只有在被选为当前目标后才实施，不因“顺手”提前接入。具体浏览器切片和节点卡见[实施计划](implementation-plan.md)。

最小必要性不降低安全、数据正确性或真实结果要求。未实现能力明确不支持，不用占位成功、假训练或模拟点击凑“能动”。必要的输入/副作用边界从首次实现就保持。

## 2. DAGpipe与AppSDK分工

DAGpipe管理项目对象流拓扑。任务先读受影响图，确认入口、依赖与结束闭合；缺边先修图。项目图放 workflows/ 顶层，执行配置引用它，不手抄第二套图。改图后validate/inspect一次；未变且证据有效时复用，不因写笔记、派单或改文字重验。L1候选图与基础规则采样图（dom-rule-sampling）及对应算子版本已升级为 0.1.0，并经 dagpipe validate/inspect 静态验证；其余远期图（dom-recognition、node-training、operation-episode）保持设计态（0.1.0-design）。静态通过不等于运行验收。流程清单与状态见 [workflows/README.md](../workflows/README.md)。

AppSDK约束需求、治理资源和适用交付入口，不能替代业务行为验收。项目存在有效.appsdk/requirements.json时，通过正式requirements show读取适用条目并据此设计/验收；不存在或为空则注明跳过，不建占位文件，不伪称已受管。本轮没有初始化AppSDK控制面，也不执行服务安装/重启。

后续确需首次AppSDK入驻时，沿既有prepare→用户确认具体项目边界→init→verify合同。不代用户确认prepare，不用fresh/reset处理普通规则更新；初始化边界确认不扩展为日常agent派发许可。AppSDK和Collab状态分属不同owner，协作未注册不阻断独立开发或质量验收。

## 3. 派发与审批边界

已授权NNAnything项目范围内，只要符合全局宿主/角色/模型/权限与文件owner原则，编排者可直接派发观察、计划、执行和Review任务，无需逐次询问。派单明确目标、读写范围、依赖、验收、停止条件与回传位置。Planner、实现者和Reviewer分离，不用低档执行角色替代独立规划或Review。

普通可逆编辑、必要测试、范围内Git提交/合流/推送沿已有授权直接完成。L1 候选切片与基础资产设计已交付；当前增量已获用户明确授权实现三类采样算子、离线 JSONL 持久化与公开采样 Consumer。重大 milestone 在作者验收与黑盒通过后整体 Review 一次，授权与 Review 不扩大至 L2-L4。

范围外或流程外删除、破坏性Git操作、生产变更、权限清除、非目标服务安装/重启仍沿全局审批边界。Review只评价实际候选，不授予额外写权限，也不替用户批准需求变更。

## 4. 本地节奏与交付方式

项目实现沿“受影响图→观察→独立计划→必要红测→唯一owner修改→真实公开入口回归”推进。先独立验证基础，再组合workflow。纯文档只做针对性检查；重大完整实现milestone在作者调试、测试和适用黑盒验收后整体Review一次，内部函数、节点和普通提交不逐次审。

代码使用全局指定的外置独占worktree；同任务先关旧树再开新树。源代码、主树和他人改动不混写。note.md汇总项目事实，过程日志放仓库外独占run目录；记录完成/失败及证据，不把每个命令变成新任务或再次验收。

标准交付为：提交已验收候选→合入main→推送origin/main并接收正常Git回执→移交必要证据→清理自有worktree/资源。远端为https://github.com/Jasonzhangf/NNAnything.git。冲突、push拒绝、CI或必需hook失败时停止受影响集成，保留原错并修对应owner，不强推、不绕hook、不伪造成功。

D0已交付合同、目录、设计图、实施计划与独立设计Review结果。当前L1交付状态见[note.md](../note.md)，运行范围见[使用指南](l1-usage.md)。L2-L4未启动，训练效果不在L1完成声明中。

## 5. 校验消融

本项目不为日常设计、派单、开发、Review、交付或清理主动计算/核对SHA、checksum，建立哈希清单、候选身份包装、冻结快照或逐字节重建。普通Git操作自然返回的提交标识可作回执，不追加比较流程。未来若实际发布确需核验，也只做该次发布必需内容。

每项测试或gate须说明它能抓住的当前失败模式。保留适用红测、真实入口行为、安全和数据正确性检查；删除无独立保障的源码文本锁定、私有结构断言、重复校验和仅为流程包装服务的步骤。不做无条件全仓/全平台回归，不为遵守规则另造证明表或审批清单。

已有有效证据直接复用。只有相关行为、依赖或环境实际变化时补受影响验证。静态DAG通过、文档存在、HTTP成功或Review通过，都不能单独证明产品行为可用。
