# NNAnything基础设计流程

用于把一个语义能力变成可实施、可训练、可独立验证的本地设计。先读[项目边界](../../../AGENTS.md)、[架构1.1/1.2](../../../docs/design.md)及受影响已有图；跨模型采集、隔离、采用和冲突规则只引用[模型演进合同](../../../docs/model-evolution.md)。不复制算法、样本schema、采用条件或全局Git/Review流程。

## 按依赖形成设计

当前标准自 2026-10-19 生效。每个新增或修改的语义及训练设计必须按 `project-design.graph.json` 顺序完成下列过程。四元素语义唯一正文为 [design.md 1.1](../../../docs/design.md)，不在本 Skill 复制。已有固定合同内的普通拟合复用有效设计；触及四元素、连线或评价时重查受影响部分，不追溯冒称历史能力已符合新合同。

| 图节点 | 必需产物与不通过条件 |
| --- | --- |
| 读取现有架构与能力缺口 | 明确范围、适用需求、现图、owner及已知/未知；缺图或未闭合先标具体缺口 |
| 定义四元素与训练反推关系 | 在领域合同明确 Goal/satisfactionThreshold/State/Action、达标依据和训练期反推关系；缺元素或用预测代替事实不通过 |
| 确定固定调用与执行责任 | 声明学生学习、手写基础、执行及观测责任；对象参数与前后条件可追踪，不把 harness 能力记作学生成果 |
| 设计数值连线与外层流程图纸 | 语义/推理与训练对象流分别闭合；复用已有图，内部数值 wire 与外层 DAG 分开；缺必要可辨输入不通过 |
| 设计独立样本及版本进化验收 | 来源分区、监督、反例及实际公开入口验收；State/satisfactionThreshold 影响输出时有区分样本，固定项不强造输入；采用规则引用原 owner |
| 校验四元素闭合与最小必要性 | DAGpipe validate/inspect 检查受影响修改图的 SESE/绑定；逐项说明移除节点、输入、wire、边或校验会失去什么必要保障；拓扑通过但语义开路或存在无必要项仍不通过 |
| 交付可实施设计或具体缺口 | 单一回执记录可实施或未就绪、具体缺口、证据、owner和恢复条件；不通过项沿后续节点传递为未就绪，不继续受影响设计/实施；各结果统一收束，修正以新轮进入 |

本图是治理资料流，不是已实现的自动审核器。DAGpipe 静态通过只证明其校验覆盖的结构；语义闭合与最小必要性由上述产物核对，不另建源码文本锁定或第二校验框架。设计准入后沿现有开发流程更新受影响 gate、取得必要红测、实现并完成真实入口回归；训练交付必须有真实拟合、回载及独立评价，不能停在治理图通过。

| 步骤 | 本项目需要明确的内容 | 落盘位置 |
| --- | --- | --- |
| 语义目标 | 一个最小Goal、对象/关系、已知State、期望效果及失败；概念、动作选择、实际效果分别验收 | 受影响领域合同；总体语义在docs/design.md |

| 连线与可辨性 | 给出能区分正确/错误的输入反例；内部特征/参数/wire/梯度和外层workflow依赖分别设计 | 算法合同与数值电路；workflows/*.graph.json及已有绑定 |

| 使用与进化 | 使用时采集的证据、当前与候选隔离、旧黄金/新独立评价；升级及冲突按唯一演进合同 | docs/model-evolution.md及领域接入说明，不复制第二套规则 |

## 三个必须在设计阶段回答的问题

可训练基本单元统一按 [docs/design.md 1.1.1](../../../docs/design.md#111-可训练基本单元与组合) 设计：最小神经元与神经元组均包含推理环、训练环、训练样本及显式权重，并使用同一类接口合同。组声明成员及必要的组合学习，不复制成员权重；确定性基础设施不虚设训练。设计时逐项列出已实现与缺口，不能把已有预测函数称为完整单元。

每项可训练语义还须绑定独立的单元升级流程 [model-evolution.graph.json](../../../workflows/model-evolution.graph.json)：自动使用采样、监督复核、隔离真实训练与回载、独立评价和旧能力回归、满足条件自动采用；回归或冲突保留当前版本并移交大模型裁决。阶段判定与冲突处理唯一正文为 [model-evolution.md](../../../docs/model-evolution.md)，不得省掉采集/训练或只存冲突不处理。设计准入与升级准入分别闭合，未实现功能列具体缺口。

1. 去掉NN后剩下什么？手写概念/参数绑定/CLI映射不冒称已学；NN负责的函数与监督单独说明。例如typed `file.property.relation.sessionCwd` observed由模型选择`pwd`，harness固定映射`/bin/pwd -P`，受信OS观测判定Goal。
2. 什么证据能抓错？例如`pwd`不改变cwd；`cd`在同一会话中后续仍有效；目录列举不拆错特殊文件名。分类正确、调用正确和实际效果不可互相替代。
3. 候选凭什么替换当前版本？没有独立证据、旧能力退化或冲突时保留当前版本；使用样本不是自动黄金；大模型改图仍是候选，后续走既有实现与验证流程。

## 复用与路由

- CLI统一目标为 [file.property.xxx](../../../docs/cli-filesystem-semantics.md)，路径、目录、普通/特殊文件的属性观测与变化共用 `cli-file-property.graph.json`；不新增零散Goal或平行核心语义。目录/文件操作完整设计目录沿 [CLI语义目录](../../../docs/cli-semantic-operations.md)。训练顺序与真实目录沙盒沿 [文件系统训练设计](../../../docs/cli-filesystem-training.md)，先CWD/pwd→cd→列举，再目录操作、文件操作；设计补全不等于已实现或授权操作真实用户文件。
- 所有CLI命令接入先沿[参数简化合同](../../../docs/cli-call-contract.md)定义固定操作和最小typed引用，再设计harness映射。NN不生成shell/原生flags，不解析输出内容；固定机器协议解码与独立OS状态观测由harness负责，不算学生能力。
- CLI命令选择统一使用同一`cli.command-policy.v1`共享矩阵；当前接入切片、head/wire词表、维度及迁移状态只读[文件系统训练合同](../../../docs/cli-filesystem-training.md)。B对象关系与R用途是概念职责，不得变成另一命令selector；参数引用由harness机械绑定，不计作模型已学的参数生成。
- DOM特征/wire、增量拟合和跨页回归：沿[本地训练Skill](../nnanything-training/SKILL.md)。本Skill不重写其算法和命令，也不把静态DOM判断当浏览器operation验收。
- 冲突先定位到观测、语义/特征、数值连线、参数、harness或评价owner。若需改连线，先更新唯一图纸与合同，再交独立计划/实现/验证；不改黄金语义或删退化例以取得升级。
- 纯合同或图纸更新交付设计和校验结果；没有真实执行不宣称训练、全模型采集或自动升级完成。实际代码开发的独立Plan、gate/红测、Review、Git交付与资源收口沿已有项目/全局规则。

最小交接说明：目标及当前设计/实现状态、I/O与owner、图纸位置、训练/独立验证分区、能抓错的反例、公开入口验收、剩余具体缺口。不要为交接新建注册表、模板目录或第二套执行框架。

## 已有能力迁移

迁移前在领域合同闭合旧入口/权重到目标合同的映射、旧输入拒绝边界、保留的独立概念职责和物理退役清单；新运行不能偷偷回退到旧模型。按名迁移只是离线起点，不证明新softmax或新语义无回归。先完成设计准入，再沿既有开发流程取得公开行为红测、迁移唯一实现、退役旧依赖和回归。训练与独立验收沿[训练Skill](../nnanything-training/SKILL.md)，Git交付沿全局流程；不为迁移新建平行运行链或治理台账。
