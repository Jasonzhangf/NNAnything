# NNAnything训练方法

CLI共享命令训练沿[文件系统训练合同](../../../docs/cli-filesystem-training.md)，调用边界沿[参数简化合同](../../../docs/cli-call-contract.md)，公开consumer为`demo:command-training`。命令选择只用一份`cli.command-policy.v1`；当前接入能力、词表、维度及退役状态由领域合同维护。动作行扩展、标签迁移、历史回放和逐命令评价以该领域合同为准；命名补零不保证共享softmax无回归。下文DOM样本、特征、迁移参考及`demo:training`命令不直接套用于CLI。

先读项目[AGENTS.md](../../../AGENTS.md)的目录边界。学生输入、wire、标签和训练I/O分别以[基础种类算法](../../../docs/basic-kinds-wiring.md)、[训练合同](../../../docs/training-workflow.md)为准。不要在Skill中另建schema、调度器或权重注册表。

若需改变语义I/O、输入、wire、节点连线或采用规则，先沿[本地设计方法](../nnanything-design/SKILL.md)更新唯一合同与图纸；已有合同内的普通拟合直接走下文。跨模型使用采集、训练/使用隔离和条件自动升级沿[模型演进合同](../../../docs/model-evolution.md)。当前离线候选仍not_applied，不能因设计要求已落盘就宣称自动升级已运行。

## 所有训练peer的硬边界

本节适用于本项目所有训练peer，包括另有领域合同的二层语义；不把下文DOM/共享命令的具体算法套到其他单元。派单必须传递本节和对应领域合同。训练目标是继承先验经验并从后验反馈增加能力，不能为取得拟合或验证通过改变问题。

实验设计归属沿[AGENTS.md「实验设计与执行分工」](../../../AGENTS.md#实验设计与执行分工)。执行者先取得Alice已落盘的概要/详细设计，按其中的命令、参数、样本、标签、分区、配方、预算和评价公式执行；已有合同内普通拟合无需重做设计。缺少决定当前步骤的设计项时，提交具体输入、缺口和事实给Alice，只停该步骤，不自行补标准或扩实验。可以报告错误分布和观察，不把自拟根因当结论。真实shell正常行为不被改造成异常训练样本，工程注入例不充当语义泛化证据。

### 标准训练入口与数据门

混合头训练先读取[三段结构与推理前置边界](../../../docs/design.md#决策单元的三段结构与推理前置边界)：确定性因素前置处理、MLP处理、确定性结果后置处理共同构成各头单元。仅优化声明的MLP学习参数；固定层声明和参数保存回载且保持不变。损失覆盖按该头已批准合同声明；完全由固定分支决定的结果不冒充MLP训练收益，相关样本仍保留在行为评价。报告分开原始MLP、固定分支和最终输出，按[混合单元审计](../../../docs/semantic-evaluation.md#混合决策单元与推理前置审计)保留分母与错误。通用推理控制和CLI命令预处理属于模型外框架，不参与权重拟合；本条不授权结构修改或把E头证据扩大到其他头。

1. trainer、evaluator、数据校验和样本converter由Alice或获授权研究员准备并测试，Alice验收后才能成为标准入口。GCM及一般执行worker只运行已验收的固定命令、config和输出目录；不得在拟合期间改训练器、目标函数、优化器、converter、评价器、标签或预算，也不得因执行报错自行修复程序。旧`fit.py`及其结果只保留为历史证据，不自动提升为标准。
2. 标准训练使用同一runner的`validate-data`、`train`、`resume`、`evaluate`显式命令和现有加速后端/checkpoint能力，不按head复制训练程序。typed config只选择已批准head、phase、输入包、TRAIN数据、固定预算和输出路径；预训练与后训练分记，后训练显式继承已验收权重。拟合进程不接收DEV/VERIFY路径，评价在独立进程运行，候选不自动采用。
3. 数据门必须先于optimizer创建。校验来源与分区、feature schema/order、缺测、语义gold与回执关联、标注一致性、hybrid固定/学习路由、重复/冲突投影和有效loss分母；只允许设计声明的格式适配，不自动丢弃、填充或改写标签。失败写`DATA_INVALID`、 offending source/row/reason，以非零退出，优化步数为0且不生成候选；失败数据不得进入train或resume。
4. 每次每个head的运行（含失败、中断、resume）自动记录机器可读和人工可读的run/head/phase、起止时间、monotonic wall/dataValidation/load/optimization/checkpointIO/evaluation耗时、optimizerSteps、processedRows、吞吐分母、stopReason/error及backend/device/dtype/threads。validation-only或未训练须记`optimizationSeconds=0`和`not_trained`；历史缺失记null/unrecorded，不做估算。检查点保存模型、optimizer、RNG、累计步数/时间和early-stop状态；resume报告累计值与本次值，不重置或重复计时。
5. 训练执行错误或数据门错误原样回传Alice/研究员。同一数据修复问题连续失败两次后停止盲派，转研究员定位和修正；只有同一数据门的精确检查通过才重置计数。独立无关任务可继续。标准环境未通过Alice的工程验收前，不宣称完成，也不启动新的实际训练或批量样本迁移。

### 阶段和数据分开

1. 预训练用于建立基础语义，单独记录样本、起点、预算、结果及基础验收。后训练须显式加载已有合格权重，只读复用原资产，结合旧train重放与新增使用监督；epoch 0核对原模型前向。候选另存，不覆盖原权重。新增参数仅按批准的名称迁移与初始化规则处理。补预训练与零起点诊断须单独标明，不能记作持续后训练成果；缺少基础资产先报告缺口，不默默重训再声称继承。
2. 来源家族/关联组先分train、development、verification，再构造实例。重复任务、同一模板的尺寸变化或同来源改名不能冒充独立来源。development可用于预声明的选参与停止；verification及其gold、原始内容、派生特征、错误清单不得交给fitter或用于样本构造、选参、挑候选和调停止点。后训练重放只取旧train，不取旧dev/verification。
3. 独立验证按事先声明的协议评价已选定候选，保留初次结果。验证暴露的反例若后续用于设计、训练或调参，须记录用途变化；可保留为已知回归，但不能再称未见验证。验证代码修复只补受影响复测并保留原错，不把复测包装为新独立证据。

### 禁止为过关修改问题

- 不得用新任务收益、平均分或总loss抵消既有已验收能力的退化。候选须逐例比较旧能力，并检查新来源实际行为；有限回归通过不等于证明所有未知输入永不遗忘。回归时保留当前版本和失败候选，不能以“增量学习必然遗忘”接受退化，也不能自行缩小旧能力范围。
- 不得按预测结果改gold、满足阈值、根Goal、评价分母、权限、预算或必要断言；不得删难例、失败、unknown、未配对项来清零。真实标注或评价器错误须单列证据交原owner更正，保留原始结果；更正不能充作学习提升。
- 不得把模型预测或期待当实际New State/监督真值；不得将缺测补成false/0或把未确认标签当黄金。有效证据下的错误预测须保留并可接受独立监督，不能因prediction错误或legal=false拒收整条离线轨迹；结构损坏、来源无效与监督未知另行隔离。禁止为采样或训练重放非法动作。
- 不得手填修复权重冒充真实拟合，不得在oracle或harness中暗加决策替学生答题，不得人为劣化baseline造收益。手工初始化与诊断对照单列，不计作训练候选通过。
- 不得在预算结束或验证失败后自动追加epoch、反复换seed、换objective、降margin或增删wire/词表以追求过关。训练前声明数据用途、重放方式、有限预算、选参范围、停止条件及旧/新验收；未覆盖的实验变化先交owner说明假设和影响，再按既有设计流程处理。无新增收益可如实交失败或无收益报告。

### 失败返回与交付

peer报告须分开列预训练、后训练、开发评价、旧能力回归、新独立验证与新进程回载；给出具名分母和retained/fixed/regressed/unknown，不以exit 0、loss下降或权重文件生成代替通过。发现数据泄漏或上述违规时停止使用受污染结果作为验收依据，保留原记录，报告受影响分区与结论并交owner修正。测试不足、监督不足或方法未通过，明确写INCOMPLETE/FAIL；不能改成PASS。旧能力与新能力无法同时满足时交owner分析表示、数据或优化原因，不授权丢弃旧知识。采用仍沿模型演进合同，不因peer训练完成自动切换。

## 开始前确定变化的owner

CLI任务走下节专属入口；本表和后续DOM步骤用于DOM特征及分类训练。

| 观察到的问题 | 先处理的owner |
| --- | --- |
| DOM可测，但输入一直缺测 | `lib/adapters/browser/`的观测与测量 |
| 输入已有信息，但没有对应评分路径 | `lib/filters/`的特征提取与wire |
| 输入和wire足以区分，但贡献不合适 | 参数profile与训练 |
| 当前基础词表无法表达目标 | 标签合同；重新复核历史other，再训练 |
| 输入正确，网页动作仍失败 | operation或观测时序；不把它自动变成分类负例 |

最小必要性：先复用已有属性。tag已有SVG值时增加评分wire，不再增加重复isSvg输入。增加新输入必须说明它能区分哪组反例，以及现有输入为什么不足。所有适用属性进入评分；不靠单一tag、role、hidden或class直接决定类别。

## CLI共享命令训练与回归

1. 先读文件系统训练合同的当前注册切片和数据合同；修改Goal/State/调用/连线先沿设计Skill闭合。固定合同内的普通拟合复用设计。每个配对须由学生输入辨别，不把teacher答案或执行结果塞入输入。
2. 来源家族先分train/development/verification；独立配方不交fitter。若扩展矩阵，从上一保存候选显式按name迁移，回放旧能力；零/冻结对照仅预测，不能替代真实拟合。
3. 用`demo:command-training`公开consumer和显式Handwired源码根拟合、保存一份候选；用`playground/cli/command-learning/reload.mjs`在新进程回载。具体参数和资产字段读领域合同，不调用DOM的`demo:training`。
4. 独立执行者只读固定候选，分别核对选头、typed参数/调用、OS实际State、满足度、失败/部分副作用及清理，报告逐命令回归。修复校验或harness错误后重跑受影响行为；输入/wire/权重未变时，不为取得绿色结果重训。
5. 训练、开发、独立验证、修复后回归和Review分别记证据。skip不算通过；测试语法或fixture失败不算产品行为红测。候选采用规则仍沿模型演进合同，离线通过不冒称已采用。交接必须区分已交付main、候选提交和未提交修复。

## DOM样本与标签

1. 原始页面／几何证据留在`training/samples/<run>/`，先声明页面、viewport/Focus、iframe/shadow、完整性和缺测范围。只采到顶层时不宣称覆盖内嵌内容。
2. class、id、正文、账号名、URL仅用于teacher证据。学生白名单不接收这些信息，也不接收绝对DOM路径或全局深度。
3. Filter输出语义与判断状态；正负例由训练任务决定。unknown/conflict不是负例，也不是黄金other。
4. 浏览器采集包遵循人工确认合同。自动分类与LLM建议另存proposal，未确认不改verified。离线teacher复核依训练合同记录实际reviewer和证据，不假冒human。
5. 单任务单标签，数组保序。包装节点不自动继承后代语义。other确认须有具体原因；combobox等边界不明时保留ambiguous。
6. 通过现有公开提取器／prepare读取请求。未复核、被排除或观测不足不能靠改状态进入训练。

## DOM现场采证与分类闭环

本节用于浏览器新增观测、未知／冲突复检和旧新比较。具体字段、前景证明与文件权重合同仍由[浏览器合同](../../../docs/browser-overlay-m1.md)维护，不在Skill复制第二套规则。

1. Agent直接读取真实DOM，复用adapter和公开候选／分类workflow，保存原始观测与保序结果。扩展用于用户验收，不能等用户重载、打开面板或采集才推进。
2. 分别统计候选合格、前置排除、观测不足、合格项的分类unknown与conflict。filtered_out、skipped和覆盖未读不是分类未知，也不是训练负例。semanticDiagnostic不改变资格、可见性、采集许可或监督真值。
3. 优化采集或缓存时，在同一页面状态对照原始入口。先检查必要DOM/CSS事实与对象关系是否丢失；不能把包装入口缺字段造成的退化当作权重问题，也不能用默认值补测量。
4. 先按实际原因路由：观测／预处理、特征／wire、参数、标签或harness。同输入换profile和同profile换观测分开比较。只有输入与评分路径足以表达目标时，才用样本拟合打分。
5. 旧新逐项比较除剩余未知外，还检查新增合格项、旧已知变ignore、焦点丢失和交互入口遗漏。跨快照引用不能按旧索引认定同一元素；只比较证据可配对项，动态／歧义／未配对项记unassessed。
6. 验收使用显式文件权重源，每次运行重读；读取或合同错误不能复用旧内存结果。改权重与改运行代码分别验收，不把换权重说成必须更新插件，也不把源码构建说成页面已加载。

## DOM标准训练与验收

1. 先读受影响现有DAG及有效证据。拓扑不变则复用，不为本轮再造图。内部wire变化更新算法owner；外部workflow变化更新对应图与绑定。
2. 固定本轮训练集、开发回放、旧黄金回归及新页面/新场景留出用途。同页面/资产/结构关联组不得跨训练与独立验证。重复快照不是独立来源。CLI的typed State配对和未绑定query边界先按文件系统合同登记，不以执行结果或teacher head替代学生输入。
3. 用真实Handwired后端拟合。显式提供源码根；缺失报错。公开起点是`npm run demo:training -- --handwired-root <源码根>`，实际数据试验使用`nnanything/training`公开接口。
4. 训练输出候选profile和逐例比较。分别报告训练、开发回放、旧黄金与未见页面，保留fixed/regressed/retained/unresolved/unassessed。不要用loss下降代替类别与状态回归。
5. 达到本轮验收即停。先用已有样本检查效果；只有明确存在覆盖缺口才扩大采集，不以增加样本代替修测量／wire。
6. 新拟合使旧校准失效。分数保持uncalibrated，候选not_applied。页面未知减少不等于准确率提高；未标注页面只报告覆盖和变化，再检查代表性新判断与剩余未知。
7. 训练须保存实际计时与行处理量；失败保留部分计时。字段与遍历口径以训练合同为准，规模实验沿公开benchmark脚本，不给旧未计时结果补估计值。拓扑变化保留旧profile与旧输出对照，版本兼容以算法合同为准，不覆盖当前采用权重。

数值拟合未达标时，先核对正式前向、缺测区间、有效梯度与目标可辨性，再按已有证据安排最小诊断。需要改优化过程时，先独立设计一个有明确停止条件的对照实验；保留失败样本、配置、计时与部分处理量，显式失败后不自动延长或重试。损失下降、单测通过、参数冻结或类别暂时正确都不能替代正式可行性与公开分类状态。原始实验结果与修正后的报告分别保留，统计修正不伪装成重新训练；脚本执行计时与Agent分析、等待时间分开报告。

特征升级、迁移和增量规则见[incremental.md](references/incremental.md)。代码实现、Review、集成和资源回收沿项目与全局既有流程，不新增审批链。
